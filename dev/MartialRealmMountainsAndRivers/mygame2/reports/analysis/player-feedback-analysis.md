## 議題 1：變化性不足

### 現況

- 玩家表示初次遊玩有樂趣，但熟悉後變化性不足。
- 目前功法體系為「6 流派 × 6 階 = 36 內功 + 36 外功」，各派系差異主要體現在傷害公式與名稱，機制上幾乎沒有差異。
- 五維平衡獲得玩家正面回饋（見議題 7），表示問題不在屬性基礎，而在功法構築與戰鬥決策。

### 診斷

- 功法數量多，但不提供不同玩法；多數情況下選「數值最高」的功法即可，導致後期決策單調。
- 戰鬥流程缺乏機制性互動（控制、增益、連擊、反制等），玩家對「我選擇這樣打」的感受不強。
- 變化性不足會直接影響熟悉後的長期遊玩意願，是本次反饋的核心問題。

### 討論方向（提案）

- 以「減少數量、增加深度」為原則，重新設計功法構築。
- 每個功法提供獨立機制，讓不同功法改變戰鬥方式，而不是只改變傷害數字。
- 使功法選擇與五維、裝備形成搭配，鼓勵玩家建立自己的流派。

### 待決策問題

1. 變化性不足要優先從「功法機制」還是「戰鬥流程」著手？
2. 玩家期望的變化性來源是「構築多樣」還是「單場戰鬥的決策深度」？
3. 是否允許同一角色的功法組合隨場景切換？

## 議題 2：功法改為功能性導向（數量 → 經驗）

### 現況

- 目前：6 流派 × 6 階 = 36 內功 + 36 外功。
- 玩家提議：同一流派內外功各留一個，改為用經驗值提升功法能力。

### 方案（已定方向 2026-08-11）

- 每個流派保留 3 本功法：**1 內功 + 1 傷害性外功 + 1 技能型外功**，共 6 × 3 = **18 本**。
- 功法等級改為「經驗培育」：學習後透過使用或擊殺怪物累積功法經驗，提升功法等級。
- 功法等級取代目前「第幾重」的定位：同流派不再有 6 本不同階的書，而是同一本功法成長到不同階段。

### 三種功法的定位

| 類型 | 定位 | 負責內容 |
|---|---|---|
| 內功 | 常駐被動 | 普通攻擊傷害公式、流派被動（屬性加成） |
| 傷害性外功 | 主動傷害 | 消耗內力的主要輸出手段，決定傷害特性 |
| 技能型外功 | 戰術功能 | 承載流派特色機制（控制、增益、位移、資源管理等） |

- 傷害性外功解決「打多少」：每流派一個，傷害特性不同。
- 技能型外功解決「怎麼打」：每流派一個，承載特色機制，是變化性的主要來源。
- 內外功搭配綁定流派，但玩家可以在練度與悟性容量允許下混用多個流派的技能型外功。

### 流派現況對照與特色機制提案

| 流派 | 內功定位 | 傷害性外功 | 技能型外功 |
|---|---|---|---|
| 金剛流 golden-body | 臂力/根骨被動 | 高倍率單體重擊 | 暴擊強化：啟用後暴擊率 ×2，持續 2 回合 |
| 追風流 swift-wind | 身法/悟性被動 | 多段連擊傷害 | 疾行：啟用後移動不受地形減免影響，持續 2 回合 |
| 赤炎流 scarlet-flame | 臂力/內息被動 | 高爆發火焰傷害 | 燎原：目標獲得燃燒，每回合損失最大血量 20%，持續 3 回合 |
| 寒水流 frost-water | 內息/根骨被動 | 穩定寒冰傷害 | 凝霜（寒毒）：目標五維 -20%，持續 2 回合 |
| 厚土流 earth-mountain | 根骨/內息被動 | 重擊倒地傷害 | 反震：自身獲得反震，被敵方造成傷害時反彈同等傷害，持續 3 回合 |
| 太虛流 void-spirit | 均衡被動 | 均衡傷害 | 迴氣（悟道）：一次性增加自身與已裝備功法的經驗值 |

### 已定案範例：金剛流技能型外功（2026-08-11）

| 項目 | 內容 |
|---|---|
| 名稱 | 暴擊強化 |
| 功能 | 啟用後獲得「暴擊率 ×2」Buff |
| 持續 | 2 回合 |
| 暴擊率上限 | 無上限（移除既有 50% 上限） |
| 使用節奏 | 與傷害性外功共用「一回合一次」規則 |

- 暴擊率公式：`臂力 × 2%`，**無上限**。
- 啟用暴擊強化後：暴擊率 = 臂力 × 4%，仍無上限。
- 移除上限原因：舊參數原本是「再次行動」，過高會破壞行動節奏，需要上限；現改為暴擊率後，高數值只增加輸出期望值，不再需要上限。
- 與傷害性外功共用每次一回合一外功的限制；施放暴擊強化的回合同樣無法施放傷害性外功。

### 已定案範例：追風流技能型外功（2026-08-11）

| 項目 | 內容 |
|---|---|
| 名稱 | 疾行 |
| 功能 | 啟用後獲得「不受地形減免影響」Buff |
| 具體效果 | 移動時所有地形一律視為草地消耗（2 體力） |
| 例外 | 牆壁仍不可通行 |
| 持續 | 2 回合 |
| 使用節奏 | 與傷害性外功共用「一回合一次」規則 |

- 目前地形消耗：草地 2／森林 4／水域 6；牆壁不可通行。
- 啟用疾行後：森林、水域一律以草地 2 體力計算；牆壁依然無法通行。
- 與現有「水行適性」Buff（水域消耗 × 0.5）同屬移動資源管理機制，可並存或另計互相效果。

### 已定案範例：赤炎流技能型外功（2026-08-11）

| 項目 | 內容 |
|---|---|
| 名稱 | 燎原 |
| 功能 | 對目標施加「燃燒」Buff |
| 燃燒效果 | 每回合損失**最大血量 20%** |
| 持續 | 3 回合 |
| 使用節奏 | 與傷害性外功共用「一回合一次」規則 |

- 燃燒傷害以**目標最大血量**為基準，不是當前血量；穩定且易於計算。
- 施放後越早造成效果越容易是死（連同本回合），越晚觸發越划算。
- 燃燒是新的狀態類型，需與現有 Buff（屬性、地形）區分，並決定堆疊規則（重複施放可疊加或刷新）。

### 已定案範例：寒水流技能型外功（2026-08-11）

| 項目 | 內容 |
|---|---|
| 名稱 | 凝霜（寒毒） |
| 功能 | 對目標施加「寒毒」Buff |
| 寒毒效果 | 目標**五維屬性 -20%** |
| 降低基準 | **基礎屬性**（不受裝備／Buff 連動影響） |
| 持續 | 2 回合 |
| 堆疊規則 | 重複施放只「刷新持續時間」，不疊加強度 |
| 使用節奏 | 與傷害性外功共用「一回合一次」規則 |

- 「6 維」為筆誤，實際降低**五維**（臂力、根骨、身法、內息、悟性）。
- 以基礎屬性為基準：避免疊加裝備 Buff 後再扣除造成的複雜連動。
- 與燃燒同為目標狀態；燃燒、寒毒的堆疊／刷新規則可統一定義（見議題 3 共通問題）。

### 已定案範例：厚土流技能型外功（2026-08-11）

| 項目 | 內容 |
|---|---|
| 名稱 | 反震 |
| 功能 | 自身獲得「反震」Buff |
| 反震效果 | 被敵方造成傷害時，對敵方造成**同等傷害** |
| 經驗判定 | 若敵方因反震傷害死亡，玩家獲得經驗值 |
| 持續 | 3 回合 |
| 使用節奏 | 與傷害性外功共用「一回合一次」規則 |

- 反震是防禦型機制：持續 3 回合，比其他流派更長，反映厚土流（根骨／內息）的防守定位。
- 「因反震死亡獲得經驗」可套用普通擊殺經驗規則，讓反震不只是防禦工具，也有主動輸出價值。
- 需確認反震傷害的計算基準：以敵方造成的傷害為準、不經過自身減傷；反震是否也觸發暴擊／功法效果待定。

### 已定案範例：太虛流技能型外功（2026-08-11）

| 項目 | 內容 |
|---|---|
| 名稱 | 迴氣（悟道） |
| 功能 | 一次性增加自身角色經驗與**已裝備功法**的經驗 |
| 角色經驗 | 固定少量值（數值後議） |
| 功法經驗 | 僅已裝備／使用的功法獲得少量固定值（數值後議） |
| 使用節奏 | 與傷害性外功共用「一回合一次」規則 |

- 這是六流派中唯一的「資源成長型」技能：不直接影響戰鬥，而是加速角色與功法成長。
- 定位符合太虛流「均衡」特色，並直接服務議題 2 的功法經驗培育機制。
- 需確認使用後是否仍屬「一回合一次」外功消耗，以及是否受「每回合一次」規則限制（待定，與其他技能型外功一致）。

### 待決策問題

1. 功法經驗來源為何？（✅ 使用功法；✅ 探索點練習事件；❌ 擊殺怪物、任務、據點教練待定）
2. 功法等級上限是否與角色等級或悟性掛鉤？（✅ 不掛鉤）

5. 技能型外功是否受悟性容量限制，還是有獨立的技能格？（✅ 方案 A：完全共用一般外功系統，受悟性容量限制，無獨立技能格）

### 技能型外功的消耗與行動規則（已定案 2026-08-11）

- **技能型外功與傷害性外功完全共用外功規則**：
  - 施放技能型外功需要消耗內力（與傷害性外功形式一致）。
  - 每回合最多施放一次外功：技能型與傷害性外功共用「一回合一次」限制，不可同回合同時施放兩者。
  - 技能型外功同樣受既有外功系統的內力、消耗與施放檢查約束。
- 範例：施放金剛流「暴擊強化」的回合無法再施放傷害性外功；玩家需在「本回合輸出」與「為後續回合鋪路」之間取捨。

### 技能型外功的容量定位（已定案 2026-08-11）

- **採方案 A：技能型外功就是一般外功，不另立類型**。
- 技能型外功直接沿用現有 `ExternalSkill` 機制：
  - 受悟性容量限制（`insightCost` 計入總容量）。
  - 消耗內力、共用「一回合一次」。
  - 承載的技能效果來自功法定義本身，不需要新技能格系統。
- 好處：工程最簡潔，與現有功法配置、悟性容量、裝備與商店系統完全相容。
- 構築取捨：技能型與傷害性外功都要搶悟性容量，玩家需在「帶幾個技能」與「投入悟性」之間抉擇。

### 外功施展對象（已定方向 2026-08-12）

- 外功資料需要新增「施展對象」欄位，至少包含：`self`、`target`、`nest`。
- `self`：技能作用於施放者自身，例如暴擊強化、疾行、反震、迴氣（悟道）。
- `target`：技能作用於敵方怪物，例如燃燒、寒毒；目標必須是可被選取的敵方角色。
- `nest`：巢穴可以成為傷害目標，因此傷害型外功可以攻擊巢穴。
- 巢穴對 Buff 類效果免疫：燃燒、寒毒、反震等狀態不可施加到巢穴；巢穴仍然可以受到外功直接傷害。
- 目標驗證應依「效果類型」分開處理：
  - 傷害效果：怪物與巢穴皆可作為目標。
  - Buff／狀態效果：僅允許可承受狀態的角色目標，巢穴直接拒絕狀態施加。
- 這個欄位也能解決目前外功預覽預設所有技能都會造成傷害的問題，讓 UI 能依 `self`／`target`／`nest` 顯示正確的施放方式。

### 舊功法處理（已定案 2026-08-11）

- **舊 36 內功 + 36 外功可以整個重新設計**，不需要保留商品、NPC 或商店形式。
- **保留內容**：各流派的傷害計算公式與流派定位（金剛、追風、赤炎、寒水、厚土、太虛）。
- **取代方式**：以「每流派 1 內 1 傷 1 技」的新結構重建功法目錄。
- **影響**：
  - 功法目錄大幅簡化，移除 6 階重複名稱。
  - 掉落池、商店、武館販售與學習流程同步改用新目錄。
  - 怪物的功法引用（`getCreatureInnerSkillId`）需改以單一內功為基礎，不再依等級挑選不同重功法（例如 `swift-wind-inner-3`）。

### 功法等級上限（已定案 2026-08-11）

- **功法等級上限不與角色等級掛鉤**：功法升級純粹由功法經驗決定，角色即使低等仍可將功法練到高等。
- **功法等級上限不與悟性掛鉤**：悟性只決定可配置功法的數量／容量，不限制單一功法能練到幾重。
- 好處：功法培育的進度感與角色升級解耦，練功成為獨立可追求的目標；角色對「把這本功法練滿」有明確的控制權。
- 後續影響：功法等級只由經驗曲線決定，需另行定義功法升級所需的經驗門檻。

### 功法經驗來源（已定案 2026-08-11）

| 來源 | 狀態 | 說明 |
|---|---|---|
| 使用功法 | ✅ 已定案 | 目前唯一來源；施放功法時獲得功法經驗 |
| 探索點練習事件 | ✅ 已定案（細節後議） | 在地圖探索點新增練習事件，可提升功法經驗或角色經驗；具體規則留待後續討論 |
| 擊殺怪物 | 待定（後議） | 擊殺怪物是否同時提供功法經驗 |
| 任務獎勵 | 待定（後議） | 告示牌任務是否提供功法經驗 |
| 據點教練 | 待定（後議） | 武館等建築是否提供訓練功能 |

### 探索點練習事件（紀錄，細節後議）

- **方向**：在地圖探索點新增「練習／修行」類事件，玩家抵達後可消耗體力進行修行。
- **目的**：提供「使用功法」以外的功法經驗來源，讓探索點不只是檢拾或事件單一用途。
- **獎勵方向**（未定）：指定流派功法經驗／指定功法類型（內、外、技能）／角色經驗值。
- **與現有系統銜接**（未定）：可結合探索事件池，依已建建築（武館、驛站）解鎖更佳修行效果。
- **待未來討論的細節**：
  1. 練習事件是「固定出現」還是「隨機事件一環」。
  2. 練習一次消耗多少體力／回合。
  3. 練習目標是「指定單一功法」還是「指定功法類型」。
  4. 高階建築是否提供加倍功法經驗的練習選項。

## 議題 3：每個功法加入特色機制

### 現況

- 目前功法機制僅有「傷害公式」與「少量 Buff」。
- 內功透過 `buffIds` 提供常駐屬性加成（如吐納功 +1 悟性）。
- 外功只有單體傷害，沒有範圍、控制、防禦或資源型。

### 方向（與議題 2 合併處理）

- 特色機制主要由「技能型外功」承載，傷害性質由「傷害性外功」承載，兩者分工。
- 每個流派 1 個技能型外功，能改變「戰鬥行為」的機制，而不只是數值。
- 範例方向：

| 機制類型 | 範例 | 適合的流派 |
|---|---|---|
| 連擊 | 擊敗目標後追加一次行動 | 追風流（暫代，待定） |
| 暴擊強化 | 獲得暴擊率 ×2 兩回合 | 金剛流（已定案） |
| 疾行 | 移動不受地形減免影響 | 追風流（已定案） |
| 燃燒 | 每回合損失最大血量 20% | 赤炎流（已定案） |
| 寒毒 | 目標五維 -20% ×2 回合 | 寒水流（已定案） |
| 反震 | 被敵方造成傷害時反彈同等傷害 | 厚土流（已定案） |
| 迴氣（悟道） | 一次性增加自身與已裝備功法經驗 | 太虛流（已定案） |
| 破防 | 無視或降低對手防禦 | 金剛流（暫代，待定） |
| 冰凍 | 降低目標下次行動或移動 | 寒水流（暫代，待定） |
| 內力轉化 | 消耗內力轉為傷害加成 | 太虛流（暫代，待定） |

## 議題 4：Buff 類道具未實裝

### 現況（已確認程式碼狀態）

- 使用道具的流程 `useItem` 已支援 `buff` 類道具，會建立 `BuffInstance` 並加入 `player.buffs`。

- `getEffectiveAttributesForPlayer` 已會套用 Buff 的屬性修正。
- `tickPlayerBuffs` 已會在回合結束時倒數並移除過期 Buff。
- 玩家回饋「buff 類道具沒有實裝」：已確認為 **UI 沒有反應，可能是 Bug**。

### 診斷結果（2026-08-11）

- **邏輯層正常**：`useItem` 建立 Buff、屬性修正、回合倒數都有實作且測試通過。
- **UI 層斷點**：`PlayerPanel.tsx` 顯示角色屬性時直接讀 `player.attributes`（基礎屬性），**沒有呼叫 `getEffectiveAttributesForPlayer` 或 `getActiveBuffsForPlayer`**。
  - 使用大力丸後 `player.buffs` 有資料（邏輯正確）
  但角色面板顯示的是基礎屬性 → 玩家看不到 +2 臂力。
  - 內功傷害預覽同樣使用 `player.attributes`，也看不到 Buff 加成。
- **角色面板沒有 Buff 顯示區**：目前完全沒有「目前 Buff 清單／剩餘回合」的 UI。
- **道具使用後回饋不明顯**：使用道具後只有背包數量減少，沒有明確實效提示。

### 修正方向（提案）

1. 角色面板屬性改用 `getEffectiveAttributesForPlayer(player)` 顯示，讓 Buff／裝備加成反映在面板。
2. 角色面板新增「目前 Buff」清單：顯示 Buff 名稱、效果、剩餘回合。
3. 道具使用結果加入明確實效回饋（如「臂力 +2（持續 3 回合）」），可放入動作結果彈窗。
4. 傷害預覽與實際傷害統一使用有效屬性，確保顯示與結算一致。

### 已定需求：玩家 UI 新增 Buff 顯示（2026-08-11）

- **位置**：`PlayerPanel.tsx`（玩家操作面板）。
- **內容**：新增「目前 Buff」區域，顯示：
  - Buff 名稱與圖示。
  - Buff 效果說明（例如「臂力 +2」）。
  - 剩餘回合數（例如 `剩 2 回合`）。
  - 常駐 Buff（剩餘回合為 null，例如內功被動）標示為持續生效。
- **資料來源**：`getActiveBuffsForPlayer(player)`（同時涵蓋道具 Buff 與內功被動 Buff）。
- **顯示時機**：有 Buff 時才顯示該區域，無 Buff 時隱藏（避免空區塊）。

### 確認事項

- 需先確認「未實裝」指的是程式沒有套用，還是玩家沒有感受到效果。
- 建議實測：使用大力丸後確認臂力是否 +2、3 回合後是否消失。

### 待決策問題

## 議題 5：官階提升太難

### 現況（已確認程式碼狀態）

- 官階門檻（`governanceRankCatalog`）：

| 官階 | 名稱 | 需求聲望 | 建築等級上限 |
|---|---|---|---|
| 1 | 流民首領 | 0 | 1 |
| 2 | 村寨掌事 | 50 | 2 |
| 3 | 鄉鎮主事 | 150 | 3 |
| 4 | 地方縣佐 | 350 | 4 |
| 5 | 一方太守 | 700 | 5 |
| 6 | 勢力盟主 | 1200 | 6 |

- 聲望來源（`CONSTRUCTION_PRESTIGE`）：建造 +5、升級 +8、修理 +3、醫療 +2、政策切換 +4。
- 玩家到達官階 2（50 聲望）需要大量建設操作，玩家感受「官階提升困難」。

### 分析

- 聲望單次給與偏低（個位數），累積到 1200 需要極大量操作。
- 建設操作還受建料、建築等級與據點條件的限制，疊加後讓玩家成長速度過慢。
- 聲望同時還控制建築上限、政策解鎖與部分事件，卡住聲望等於卡住多條成長線。

### 調整方向（已定案 2026-08-11）

- **官階需求聲望全部降低一半**，先以此數值觀察節奏，再依實測調整。

| 官階 | 名稱 | 原本需求聲望 | 降低一半後 |
|---|---|---:|---:|
| 1 | 流民首領 | 0 | 0 |
| 2 | 村寨掌事 | 50 | 25 |
| 3 | 鄉鎮主事 | 150 | 75 |
| 4 | 地方縣佐 | 350 | 175 |
| 5 | 一方太守 | 700 | 350 |
| 6 | 勢力盟主 | 1200 | 600 |

- 單次建設聲望獎勵（建造 +5、升級 +8、修理 +3、醫療 +2、政策切換 +4）暫不調整，先看降低門檻的效果。
- **影響**：`governanceRankCatalog` 中 6 個 `requiredPrestige` 值；`governanceRules.test.ts` 中多處以 50／150／350／1200 驗證官階與下一需求的測試需同步更新。

### 待決策問題

1. 要調整哪一個方向：降低門檻、提高獎勵、新增來源，還是三者並行？（✅ 降低門檻，已定案）
2. 目標節奏：一場完整對局內，玩家期望達到哪個官階？（✅ 至少第四階級「地方縣佐」）
3. 官階與建築等級一對一掛鉤是否保留？（✅ 保留）

### 目標節奏與掛鉤（已定案 2026-08-11）

- **一場完整對局，玩家預期至少培養到第四階級（地方縣佐）**。
- 降低一半後，第四階級需求為 **175 聲望**，作為正常對局的達標線。
- 第五（太守 350）與第六階（盟主 600）保留為後期或高投入玩家的追求，不強求一般對局達成。
- **官階與建築等級一對一掛鉤保留**：玩家要建造／升級更高級建築，仍須提升官階（官階 N → 建築上限 N 級）。
- 後續驗證方向：實測一場對局玩家的聲望累積速度，若達不到第四階級，再考慮提高單次建設聲望獎勵或新增聲望來源。

## 議題 6：30 回合全員攻城

### 現況（已確認程式碼狀態）

- `CreatureBehaviorType` 已定義 `sieger`（攻城型）。
- `CREATURE_AGGRO_RANGES`：攻城型仇恨距離 7（最高）。
- 目前巢穴與怪物由行為類型決定目標；攻城型會優先攻擊據點、資源點與防禦設施。
- 目前沒有「回合到點全員轉攻城」的機制。

### 方案（已定方向 2026-08-11）

- **取代原「30 回合全員轉攻城」設計**，改為漸進式巢穴轉型：
- **巢穴每次成功生成怪物時，有 30% 機率轉為攻城型**。
- 巢穴轉為攻城型後，未來生成的新怪物（以及巢穴本身行為）皆為攻城型。
- 攻城型怪物會集中攻擊據點與防禦設施，形成漸進的終局壓力。
- 優於原本設計的原因：壓力是逐步累積的，玩家能感受到「巢穴一個一個開始轉型」的張力，而不是某個回合突然全部敵對化。
- 轉換時需要 UI 提示與日誌（例如「怪物巢穴變成攻城型」）。

### 待決策問題

1. 巢穴轉攻城型是「永久轉變」還是「僅當次生成」？（✅ 永久轉變）
2. 現存怪物是否會跟著巢穴轉型，還是只有「轉型後新生成」的怪物為攻城型？（✅ 非攻城型怪物存活滿 20 回合後自動轉為攻城型）
3. 攻城型怪物是否獲得屬性或數量加成？（✅ 暫時不需要）
4. 越後期（回合越晚）是否提高轉型機率（例如每 10 回合機率 +10%）？（✅ 同意，方向寫入文件；具體倍率細節後議）
5. 原本的「30 回合」時間點是否完全移除，只保留機率制？（✅ 完全移除）

### 已定案規則（2026-08-11）

- **巢穴轉型為永久**：一但轉為攻城型就不可逆，之後每次生成的新怪物皆為攻城型。
- **現存怪物自動轉型**：任何非攻城型怪物，從出生起**存活滿 20 回合**後自動轉為攻城型。
- **無屬性加成**：攻城型怪物不獲得額外屬性或數量加成，僅改變行為目標（集中攻擊據點與防禦設施）。
- **移除 30 回合機制**：不再有「第 30 回合全員轉攻城」的強制轉換。
- **機率遞增（方向已同意）**：巢穴轉型機率隨遊戲回合推進提高，例如每 10 回合機率 +10%（具體起始值與增幅、是否封頂，細節後議）。
- 轉換時需要 UI 提示與日誌（例如「怪物巢穴變成攻城型」「某怪物已轉為攻城型」）。

## 議題 7：最大內力改為內息 × 2

### 現況（已確認程式碼狀態）

- 目前公式：`getMaxInnerPower = 內息 × 3`
- 其他屬性公式：
  - 最大生命：根骨 × 3
  - 最大體力：身法 × 1
  - 最大內力：內息 × 3

### 方案（已定案 2026-08-11）

- 將最大內力公式改為 `內息 × 2`。
- 內力主要用於外功施放，內息同時影響內功傷害公式（部分流派：臂力 × 0.5 + 內息 × 0.5）。
- 降低最大內力會：降低外功的使用次數上限，讓內力管理更有取捨。

### 影響

- 影響所有角色（玩家與怪物）的內力上限。
- 可能影響外功使用節奏與內力恢復的平衡。
- 需同步檢查內力恢復（每回合 5%）是否要調整。
- **實作**：`getMaxInnerPower` 由 `內息 × 3` 改為 `內息 × 2`；相關測試（`playerStatsRules`、`types.test` 等）需同步更新。

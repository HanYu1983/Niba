# 遊戲系統設計與創意總規劃

## 1. 文件目的

- 定義目前遊戲的核心體驗與系統定位。
- 整合道具、裝備、功法、建築、探索與世界事件規劃。
- 記錄系統間的互動閉環、風險與後續開發優先級。
- 提供可直接拆分成工程與遊戲設計任務的共同文件。

## 2. 核心幻想與設計支柱

### 2.1 核心幻想

- 玩家是一名在危險荒野中建立勢力的冒險者。
- 每次移動都可能帶來資源、風險、情報或戰術位置。
- 玩家不只清除 Creature，也會探索、經營並改變地圖。

### 2.2 設計支柱

- **探索感**：未知地點、事件與寶箱提供發現動機。
- **選擇感**：玩家在安全收益與高風險高報酬間做決定。
- **成長感**：玩家、據點、裝備與功法逐步成長。
- **世界反應**：玩家行動會影響資源、Creature、NPC 與地圖狀態。
- **資訊價值**：情報協助玩家判斷風險，而不是只依靠運氣。

## 3. 目前系統總覽

| 系統 | 目前功能 | 桌遊定位 | 完成度 |
|---|---|---|---|

| 裝備 | 武器、防具、配件三槽、五維修正、獨立實例、耐久 | 長期成長與戰鬥取捨 | 中 |

| 探索事件 | 事件點、選項、情報與風險 | 非戰鬥探索內容 | Planned |

## 4. 目前核心循環

```text
探索地圖
→ 發現資源點、道具點、Creature、巢穴或事件
→ 進行戰鬥與互動
→ 消耗生命、體力、內力與裝備耐久
→ 獲得道具、裝備或功法
→ 回到據點進行任務、修理與建設
→ 使用建築能力支撐後續探索
```

## 5. 四個核心系統評估

### 5.1 功法

#### 目前作用

- 內功決定普通攻擊的基礎傷害。
- 外功提供特殊攻擊與內力消耗。
- 悟性限制內功與外功容量。
- 巢穴摧毀後可學習尚未掌握的內功或外功。

#### 目前不足

- 外功數量少，戰術差異有限。
- 功法切換成本仍需明確化。
- 不同功法的場景用途尚不夠分明。

#### 後續方向

- 增加單體、範圍、控制、防禦或資源型外功。
- 設定功法切換限制，例如每回合一次或消耗行動。
- 讓功法與裝備形成明確搭配。

### 5.2 裝備

#### 目前作用

- 武器、防具、配件各裝備一件。
- 裝備修正五維屬性。
- 裝備為不可堆疊的獨立實例。
- 每件裝備具有獨立耐久。
- 玩家攻擊消耗武器與配件耐久。
- 玩家被攻擊消耗防具與配件耐久。

#### 目前不足

- 尚未有修理機制。
- 裝備損壞後補救手段不足。
- 裝備差異主要仍是數值差異。

#### 後續方向

- 新增據點修理功能。
- 修理消耗建料、金錢或特殊材料。
- 設計高屬性低耐久、低屬性高穩定等取捨。

### 5.3 道具

#### 目前作用

- 療傷藥恢復生命。
- 回氣丹恢復體力。
- 道具點與生物擊殺可掉落消耗品。
- 道具使用受目前回合與資源上限限制。

#### 目前不足

- 使用情境偏直覺，數值不滿就使用。
- 戰術型道具種類少。
- 攜帶上限與使用代價尚未明確。

#### 後續方向

- 明確定義使用道具是否消耗行動。
- 考慮攜帶數量上限。
- 後續加入攻擊型、控制型或探索型道具。

### 5.4 建築

#### 目前作用

- 告示牌提供據點任務。
- 建築消耗建料。
- 據點擁有血量、建料與建築列表。
- 資源點提供建料收入。

#### 目前不足

- 部分效果仍停留在描述層。
- 建築先後選擇不夠明確。
- 建築與裝備修理、巢穴威脅連結不足。

#### 後續方向

- 告示牌：提供任務與金錢。
- 城牆：提升據點最大生命；本遊戲不使用獨立防禦力數值。
- 防衛營：提升據點或附近友軍最大生命。
- 修理設施：消耗建料修理裝備。
- 防禦設施：在據點周圍 6 格內消耗建料建造木柵、瞭望塔或箭塔；箭塔在 Creature 回合自動攻擊周遭 3 格內的 Creature。
- 據點內建築與地圖防禦設施為兩個獨立列表；目前遊戲只使用地圖 `watchtower`「瞭望塔」，不提供據點內瞭望塔或指揮塔。
- 防禦設施是佔用地圖格子的獨立物件，具有 HP，能改變 Creature 路線、提供最大生命加成或提供視野。
- 詳細資料模型、建造流程、Creature 互動與驗收標準見 [`reports/defense-structures-design.md`](defense-structures-design.md)。

## 6. 系統互動閉環

```text
巢穴
→ 提供功法、裝備與其他戰利品

據點
→ 提供任務、修理、建設與安全補給

建料
→ 建造據點周圍防禦設施

防禦設施
→ 阻擋或延緩 Creature，並可能提供視野與防守能力

資源點
→ 提供建料與據點發展資源

建築
→ 提升據點安全、任務收益、修理能力或區域能力

裝備
→ 提升戰鬥能力，但受到耐久限制

功法
→ 決定角色戰鬥方式與內力分配

道具
→ 解決短期生命、體力與探索危機
```

## 7. 目前最大設計問題：系統彼此平行

目前容易形成：

```text
撿道具 → 使用道具
撿裝備 → 裝備
學功法 → 切換功法
建築 → 解鎖任務
```

各系統都有功能，但玩家未必需要在它們之間做艱難選擇。後續應優先增加有限行動下的決策：

- 建料要蓋建築，還是修理裝備？
- 現在用道具，還是保留到危險區域？
- 挑戰巢穴取得功法，還是先回據點補給？
- 使用高屬性低耐久裝備，還是保留穩定裝備？
- 切換高傷害功法，還是保留內力使用外功？

## 8. 探索與世界事件提案

### 8.1 隨機事件點

#### 概念

- 地圖生成可點擊事件點。
- 玩家靠近一格後可調查。
- 事件提供多個選項，而不是單一獎勵。

#### 事件範例

- 失散商隊：護送、交易或掠奪。
- 受傷旅者：消耗藥品救治，獲得情報或聲望。
- 神秘祭壇：獲得屬性加成，但可能召喚 Creature。
- 廢棄營地：搜尋物資，可能發現陷阱。
- 被封鎖道路：花費建材清理，開啟捷徑。

#### 狀態

- `hidden`：尚未發現。
- `available`：已發現且可以互動。
- `resolved`：本局已完成。
- `expired`：因回合或世界狀態失效。

#### 例外處理

- 非相鄰只能查看資訊，互動按鈕 disabled。
- 玩家已結束回合時，互動按鈕 disabled。
- 同一事件不可重複領取獎勵。
- 探索事件 MVP、失散商隊選項、條件、獎勵與驗收標準見 [`reports/exploration-events-design.md`](exploration-events-design.md)。

### 8.2 寶箱與遺物

#### 稀有度

- 普通：金錢或少量建材。
- 稀有：裝備、技能書或屬性加成。
- 傳說：改變玩法的遺物，例如降低地形體力消耗。
- 詛咒：高獎勵，但附帶負面狀態或 Creature 事件。

#### 例外處理

- 寶箱被其他玩家先開啟時，顯示已探索。
- 非相鄰只能查看位置與稀有度提示。
- 背包不足時允許放棄或延後取得，不得無提示消失。

### 8.3 NPC 與商隊

- 目前不建立獨立 NPC 系統。
- 商隊、旅者與情報販子先以探索事件中的角色呈現。
- 商隊 MVP：交易、護送或掠奪。
- 受傷旅者事件：消耗藥品救治，獲得情報或聲望。
- 情報販子事件：以一次性事件揭示 Creature、巢穴或資源點。
- 商人、治療師、傭兵與任務 NPC 的長期服務系統延後處理。

#### 互動原則

- 詳情 modal 顯示身份、位置、服務與價格。
- 交易確認前顯示資源變化。
- 金錢或物品不足時，確認按鈕 disabled 並顯示原因。
- 以上互動目前由探索事件 modal 與事件選項提供，不使用獨立 NPC 狀態。
- 詳細事件規格見 [`reports/exploration-events-design.md`](exploration-events-design.md)。

### 8.4 中立據點與區域控制

#### 地標範例

- 瞭望塔：擴大探索視野。
- 廢棄礦場：每回合提供建材。
- 旅店：恢復生命與體力。
- 橋頭堡：降低附近地形移動成本。
- 古代遺跡：提供特殊研究或被動能力。

#### 佔領流程

- **Stage**：玩家接近中立地標。
- **Player Action**：點擊地標並選擇佔領或調查。
- **System Response**：檢查距離、回合狀態與前置條件。
- **State Change**：更新所有權、收入或視野範圍。
- **Exception Handling**：條件不足時顯示原因，不消耗行動。

### 8.5 視野與迷霧

- 初始只顯示玩家、據點與已探索範圍。
- 移動、瞭望塔與情報事件可擴大可見區域。
- 未探索區域不得顯示 Creature 詳細資料。
- 曾探索但目前不在視野內的區域只顯示地形輪廓。
- 重要劇情事件必須提供最小必要提示，避免完全錯過。
- 戰爭迷霧的詳細資料模型、MVP 規則、Store 驗證與分階段實作，見 [`reports/fog-of-war-design.md`](fog-of-war-design.md)。

### 8.6 動態世界事件

每回合最多觸發一個主要世界事件，例如：

- Creature 向資源點或據點遷移。
- 資源點暫時枯竭或產量變化。
- 商隊在隨機地點出現。
- 區域受到污染，地形移動成本提高。
- 敵方對據點發動攻擊。
- 新事件點或寶箱生成。

## 9. 勝利、失敗與對局壓力

### 9.1 正式勝利條件

- 摧毀最終 Boss 巢穴。
- Boss 巢穴被摧毀並完成結果彈窗確認後，立即判定玩家勝利。
- 普通巢穴不是勝利條件，但可以提供功法、裝備與其他戰利品，並降低地圖威脅。

### 9.2 正式失敗條件

- 所有據點被 Creature 或其他世界事件破壞。
- 所有玩家死亡。
- 任一條件成立後，立即進入遊戲失敗狀態，不再接受一般玩家 action。

### 9.3 回合與持續壓力

- 遊戲不設回合上限。
- Creature 與巢穴會持續生成敵人，形成自然時間壓力。
- 玩家若不主動推進探索、成長與 Boss 戰，最終會因據點被破壞或玩家死亡而失敗。
- 回合數仍保留作為世界事件、巢穴生成與資源收入的時間尺度，不作為直接失敗條件。

### 9.4 行動取捨

需要明確定義下列行動是否互相競爭：

- 移動
- 攻擊
- 使用道具
- 裝備或卸下裝備
- 切換功法
- 採集資源
- 執行任務
- 建造建築
- 修理裝備

## 10. UI 與彈窗規範

### 10.1 地圖 marker

- 每類物件使用獨立 marker class，例如 `.event-point-marker`。
- Marker 必須支援滑鼠、Enter 與 Space。
- 點擊 marker 必須阻止事件冒泡，避免誤觸移動。
- Tooltip 顯示名稱與目前狀態。

### 10.2 詳情彈窗

- **Title**：物件名稱與「詳細資料」。
- **Message**：位置、狀態、獎勵與互動條件。
- **Buttons**：確認、取消、關閉。
- **States**：enabled、disabled、completed、unavailable。
- **Interaction Flow**：詳情 → 確認 → 結算 → 結果彈窗。
- **Error Handling**：條件不符、目標不存在、重複結算須保留狀態並顯示原因。

### 10.3 結果彈窗

- 結果彈窗在狀態更新後顯示。
- 必須列出實際結算結果，不只顯示預期值。
- 多項獎勵使用清單逐項列出。
- 關閉結果彈窗後，地圖與玩家面板顯示最新狀態。
- 若 action 尚未完成回合流程，使用 continuation 延後回合推進。

## 11. 短期開發里程碑

### Milestone 1：探索事件 MVP

#### Task Item

- 新增 `EventPointState`。
- 生成事件點與 marker。
- 新增事件詳情彈窗。
- 實作相鄰判定與事件選項。
- 實作確認後結果彈窗。
- 新增完成狀態，避免重複領取。

#### Acceptance Criteria

- 玩家可點擊事件點。
- 非相鄰只能查看，不能執行。
- 相鄰且回合有效時可確認。
- 獎勵只結算一次。
- 結果彈窗顯示事件結果與獎勵。

#### Test Method

- 測試相鄰與非相鄰位置。
- 測試玩家已結束回合。
- 測試重複確認。
- 執行 `npm test`、`npm run lint`、`npm run build`。

### Milestone 2：寶箱與探索獎勵

#### Acceptance Criteria

- 寶箱可查看、開啟並標記已探索。
- 獎勵正確加入玩家資源或背包。
- 空間不足時有清晰提示。
- 結果彈窗顯示取得物品。

#### Test Method

- 測試普通、稀有、傳說與詛咒寶箱。
- 測試空間不足與重複開啟。
- 測試回合切換後獎勵仍保存。

### Milestone 2.5：探索事件 MVP

#### Acceptance Criteria

- 玩家可發現並點擊事件點。
- 失散商隊提供交易、護送與掠奪三個選項。
- 非相鄰或條件不足時只能查看，不能結算。
- 每個選項產生不同成本、獎勵或風險。
- 事件只能結算一次。
- 結果彈窗確認前不推進玩家回合。

#### Test Method

- 測試事件 marker 滑鼠與 Enter/Space 操作。
- 測試相鄰、非相鄰與玩家已結束回合。
- 測試金錢/道具/建料不足。
- 測試交易、護送與掠奪的不同結果。
- 執行 `npm test`、`npm run lint`、`npm run build`。

#### Detailed Design

- 詳細規格：[`reports/exploration-events-design.md`](exploration-events-design.md)

### Milestone 3：中立據點與區域控制

#### Acceptance Criteria

- 玩家可調查並佔領中立地標。
- 佔領效果可在地圖與玩家面板看見。
- Creature 可以威脅或重新奪回地標。
- 區域控制狀態可保存並更新。

### Milestone 4：戰爭迷霧 MVP

#### Acceptance Criteria

- 新遊戲不顯示全圖所有互動物件。
- 玩家初始視野符合基礎視野距離。
- 玩家移動後新的格子加入已探索資料。
- 視野外 Creature 與巢穴不可見且不可攻擊。
- Debug 地圖可使用 `revealed` 模式查看完整地圖。

#### Test Method

- 測試初始視野與移動後探索範圍。
- 測試 Creature 進入/離開視野。
- 測試視野外攻擊與外功被 Store 拒絕。
- 執行 `npm test`、`npm run lint`、`npm run build`。

#### Detailed Design

- 詳細規格：[`reports/fog-of-war-design.md`](fog-of-war-design.md)

### Milestone 5：據點周邊防禦設施 MVP

#### Acceptance Criteria

- 玩家可在據點曼哈頓距離 6 格內選擇可建造空格。
- 建造會消耗據點建料，並在結果確認後結束玩家回合。
- 木柵與瞭望塔可作為地圖上的獨立物件顯示。
- 防禦設施會佔用格子，不能與其他物件重疊。
- Debug 地圖可快速測試建造範圍與 Creature 路線影響。

#### Test Method

- 測試 6 格內外位置。
- 測試建料不足、格子被佔用與地形不符。
- 測試建造結果彈窗 continuation。
- 執行 `npm test`、`npm run lint`、`npm run build`。

#### Detailed Design

- 詳細規格：[`reports/defense-structures-design.md`](defense-structures-design.md)

## 13. 平衡與風險

- Creature 戰鬥與獎勵仍需持續平衡，避免玩家過早取得過多永久戰鬥加成。
- 優先提供一次性資源、情報與位置優勢，再逐步加入永久能力。
- 高報酬事件應加入體力、金錢、回合或戰鬥風險。
- 每次平衡調整只修改一至兩項參數，並重新執行戰鬥模擬。
- 事件獎勵不應大幅超過單次任務與採集收益，避免最優策略固定化。
- 每回合最多觸發一個主要世界事件，避免資訊過載。
- 事件不得無預警摧毀玩家核心進度。

## 14. 成功指標與總結

### 成功指標

- 玩家每回合至少有兩種以上合理行動選擇。
- 地圖上的非戰鬥互動比例逐步提高。
- 玩家能理解每個互動的條件、風險與獎勵。
- 事件結果可被清楚回顧，不依賴玩家記憶。
- 新系統不破壞現有任務、採集、戰鬥與回合流程。
- 道具、裝備、功法、建築至少有兩個系統互相影響。

### 總結

目前系統數量已足夠支撐小型桌遊 Prototype。下一階段不應優先增加大量新系統，而應集中在：

- 建築實際效果。
- 裝備修理與耐久閉環。
- 道具使用取捨。
- 功法戰術差異。
- 勝利與失敗條件。
- 探索事件與區域控制。
- 系統之間的資源與行動衝突。

目標是讓玩家不只是使用多個系統，而是在系統之間持續做出有代價的選擇。

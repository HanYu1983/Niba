# 據點周邊防禦設施開發設計文件

## 1. 文件目的

- 將據點建設從據點內部建築擴展到地圖上的防禦設施。
- 建立據點周圍空間、建料與 Creature 威脅之間的戰略取捨。
- 定義可直接拆分成工程任務的資料模型、建造流程與驗收條件。
- 與現有據點、資源點、回合、Creature AI、行動結果彈窗及戰爭迷霧保持一致。

## 1.2 建築分類與命名規範

遊戲中的建設分為兩個獨立系統，不共用玩家認知上的「地圖建築」概念：

### 據點內建築（Base Buildings）

- 建造於據點內部。
- 通常每種類型只能建造一次。
- 不佔用世界地圖格子。
- 主要提供據點功能、任務、補給、修理或區域能力。
- 由 `BaseState.buildings` 管理。
- 建議資料目錄名稱：`baseBuildingCatalog`。

| 類型 | 名稱 | 建議成本 | 核心功能 | 開發階段 |
|---|---|---:|---|---|
| `board` | 告示牌 | 0 | 解鎖據點任務 | 已有 |
| `wall` | 強化城牆 | 30 | 提升據點最大生命 | 已有，效果待補 |
| `barracks` | 防衛營 | 50 | 提升據點影響範圍內玩家最大氣血，不恢復當前氣血 | 已有，效果已接入 |
| `workshop` | 修理工坊 | 60 | 提供裝備修理預覽與確認修理 | 已有，效果已接入 |
| `warehouse` | 建料倉庫 | 40 | 提高建料上限，增加資源點採集建料 | 已有，效果已接入 |
| `infirmary` | 醫療室 | 50 | 提供「就醫」以恢復少量氣血與內力 | 已有，效果已接入 |

### 地圖防禦設施（Defense Structures）

- 建造於據點周圍地圖格。
- 每個設施有獨立位置、生命值與所屬據點。
- 會佔用地圖格子，可能阻擋 Creature 或改變路線。
- 未來可被攻擊、摧毀、維修或拆除。
- 由 `GameState.defenseStructures` 管理。
- 建議資料目錄名稱：`defenseStructureCatalog`。

| 類型 | 名稱 | 成本 | 最大生命 | 核心功能 | 開發階段 |
|---|---|---:|---:|---|---|
| `barricade` | 木柵 | 10 | 50 | 阻擋 Creature | 建造 MVP 已有 |
| `watchtower` | 瞭望塔 | 20 | 80 | 提供局部視野 | 建造已有，效果暫緩 |
| `arrow-tower` | 箭塔 | 30 | 100 | 固定範圍自動攻擊 | 建造已有，效果暫緩 |
| `stone-wall` | 石牆 | 25 | 120 | 強力阻擋 | 後續 |
| `trap` | 陷阱 | 15 | 20 | Creature 經過時造成傷害 | 後續 |
| `alarm-post` | 警戒柱 | 20 | 40 | 提前揭示附近敵人 | 後續 |

### 命名規則

- 遊戲目前只使用地圖防禦設施 `watchtower`「瞭望塔」；據點建築不提供瞭望塔或指揮塔。
- 據點建築與地圖防禦設施仍由不同資料結構管理，避免 UI、Store action 與平衡規則混淆。

## 2. 核心設計概念

```text
資源點
→ 產出建料
→ 據點消耗建料建造防禦設施
→ 防禦設施改變地圖路線、最大生命或視野
→ Creature 攻擊設施並造成損耗
→ 玩家選擇維修、替換或放棄設施
```

防禦設施不是單純的據點數值加成，而是佔用地圖格子的實體物件。

## 3. 建造範圍規則

### 3.1 範圍定義

- 以據點為中心。
- 使用曼哈頓距離。
- 基礎建造範圍為據點周遭 6 格。
- **建造範圍隨據點所屬玩家官階增長**：官階每高 1 級，建造距離 +1；官階 6 級總共 +5，最大可達 11 格。

```ts
const BASE_BUILD_RANGE = 6
// 官階加成：官階 1 = +0，官階 2 = +1，… 官階 6 = +5
const rankBonus = Math.max(0, getGovernanceRankNumber(baseOwnerPrestige) - 1)
const buildRange = BASE_BUILD_RANGE + rankBonus

const distance =
  Math.abs(base.row - target.row) +
  Math.abs(base.column - target.column)

const canBuildInRange = distance <= buildRange
```

#### 官階對應建造距離

| 官階 | 建造距離（含基礎 6） |
|---|---:|
| 1 | 6 |
| 2 | 7 |
| 3 | 8 |
| 4 | 9 |
| 5 | 10 |
| 6 | 11 |

> **註**：官階加成以「據點所屬玩家」的官階為準（而非目前行動玩家）。若據點無明確所屬玩家（如中立／未佔領），回退為基礎範圍 6 格。

### 3.2 不可建造條件

以下格子不可建造：

- 據點所在格。
- 其他玩家所在格。
- Creature 所在格。
- 巢穴所在格。
- 資源點所在格。
- 道具點所在格。
- 其他防禦設施所在格。
- 牆體。
- 不符合設施地形要求的格子。
- 超過據點建造範圍（基礎 6 格 + 官階加成）的格子。

### 3.3 建造模式高亮

進入防禦建設模式後：

- 只高亮據點建造範圍（基礎 6 格 + 官階加成）內的可建造空格。
- 已佔用或不可建造格不高亮。
- 提示內容顯示目前據點、建料與可建造範圍。
- 取消建造不消耗建料、不結束回合。

### 3.4 地形限制

部分設施僅能建造於特定地形（`terrainRequirements`）：

- **通用設施**（木柵、瞭望塔、箭塔等，見 §10）不限地形，與五行特有設施共存。
- **五行地形專屬設施**（§11）僅能建造於與其五行對應的地形，例如「金系塔」只能蓋在山嶽上。
- 建造模式高亮時，除了據點建造範圍（基礎 6 格 + 官階加成）與空格判定，也需依所選設施的 `terrainRequirements` 過濾可建造格；不符地形的格子不高亮、不可選。
- 地形判定與天地共鳴（§12）採同一套地形→五行對應，保持世界觀一致。

## 4. 資料模型

> 本文件的 `DefenseStructure*` 型別只適用於地圖防禦設施；據點內建築使用獨立的 `BaseBuilding*` 型別與 catalog。

### 4.1 防禦設施類型

```ts
type DefenseStructureType =
  // 通用設施
  | 'barricade' | 'watchtower' | 'arrow-tower'
  // 五行地形專屬（§11）
  | 'earth-pillar' | 'wood-lodge' | 'water-bastion' | 'fire-beacon' | 'metal-shrine'
```

### 4.2 防禦設施狀態

```ts
type DefenseStructureState = {
  id: string
  type: DefenseStructureType
  name: string
  description: string
  position: Position
  ownerBaseId: string
  health: number
  maxHealth: number
  constructionCost: number
  healthBonus: number
  blocksMovement: boolean
}
```

### 4.3 建造目錄

```ts
type DefenseStructureDefinition = {
  type: DefenseStructureType
  name: string
  description: string
  icon: string
  constructionCost: number
  maxHealth: number
  healthBonus: number
  blocksMovement: boolean
  providesVision: boolean
  attackRange: number
  attackDamage: number
  terrainRequirements?: TerrainType[]
}
```

據點內建築後續應與防禦設施使用不同型別：

```ts
type BaseBuildingDefinition = {
  type: BaseBuildingType
  name: string
  description: string
  icon: string
  constructionCost: number
  unique: boolean
  effects: BuildingEffect[]
}

type BaseBuildingState = BaseBuildingDefinition & {
  id: string
  builtRound: number
}
```

目前程式仍可暫時使用既有 `BaseBuilding`，但新增據點內建築時應優先往 `baseBuildingCatalog` 與 `BaseBuildingDefinition` 遷移。

## 5. 第一版設施規格

### 5.1 木柵

- 類型：`barricade`
- 建造成本：10 建料
- 最大生命：50
- 效果：阻擋 Creature 通行
- 主動攻擊：無

### 5.2 瞭望塔

- 類型：`watchtower`
- 建造成本：20 建料
- 最大生命：80
- 效果：增加戰爭迷霧視野
- 主動攻擊：無
- 第一版定位：探索與情報支援

### 5.3 箭塔

- 類型：`arrow-tower`
- 建造成本：30 建料
- 最大生命：100
- 效果：Creature 回合自動攻擊自身周遭 3 格內的 Creature。
- 攻擊規則：每座箭塔選擇射程內距離最近的存活 Creature，每回合最多攻擊一次。
- 基礎傷害：10 點固定傷害。
- 目標選擇：同距離時依 Creature 陣列順序決定，後續可改為血量最低或威脅最高。
- Creature 被擊敗後立即從該回合後續移動與攻擊流程排除。
- 第一版定位：提供固定、可預期的據點周邊防守火力。

## 6. 建造流程

### Stage 1：開啟防禦建設

- **Player Action**：玩家從據點詳細 modal 點擊「防禦建設」。
- **System Response**：顯示設施清單、建料、建造範圍與可用設施。
- **State Change**：`operation = building-defense`。
- **Exception Handling**：若玩家不是目前玩家、已結束回合、死亡或 Creature 正在行動，按鈕 disabled。

### Stage 2：選擇設施

- **Player Action**：玩家選擇木柵、瞭望塔或箭塔。
- **System Response**：顯示建造成本、生命值、效果與可建造格。
- **State Change**：`operation` 保存待建造設施類型。
- **Exception Handling**：建料不足時不可確認，並顯示缺少建料數量。

### Stage 3：選擇位置

- **Player Action**：玩家點擊據點建造範圍（基礎 6 格 + 官階加成）內的可建造空格。
- **System Response**：顯示建造確認資訊。
- **State Change**：保存待建造位置。
- **Exception Handling**：位置被佔用、超出範圍或地形不符時不建立設施，也不消耗建料。

### Stage 4：確認建造

- **Player Action**：玩家確認建造。
- **System Response**：建立防禦設施、扣除據點建料、顯示行動結果彈窗。
- **State Change**：新增 `DefenseStructureState`，玩家回合標記結束。
- **Exception Handling**：確認時必須再次驗證建料、位置、玩家回合與據點存在，避免 preview 過期造成非法建造。

### Stage 5：結果確認

- **Player Action**：玩家確認結果彈窗。
- **System Response**：執行 `end-player-turn` continuation。
- **State Change**：進入下一位玩家或 Creature 回合。
- **Exception Handling**：結果彈窗關閉與確認共用同一 continuation，避免停留在半回合狀態。

## 7. Creature 互動

> 所有地圖防禦設施皆採用相同的木柵規則：佔用地圖格、阻擋 Creature、可被 Creature 攻擊，生命值歸零後移除。

### 7.1 移動阻擋

- 所有防禦設施都會加入 Creature 尋路阻擋位置，不區分木柵、瞭望塔或箭塔。
- Creature 不可進入或穿越任何防禦設施所在格。
- Creature 優先嘗試繞路；若前往目前目標的路徑被防禦設施阻擋，則在相鄰位置攻擊該設施。
- 防禦設施不應永久封鎖地圖，必須具有生命值。

### 7.2 Creature 攻擊設施

- Creature 不會為了攻擊遠處設施而偏離目前目標。
- Creature 的目標優先級維持目前規則：玩家或資源點優先；設施只在阻擋前進路徑時成為攻擊目標。
- Creature 攻擊設施時只扣除設施生命值。
- Creature 每回合對阻擋路徑的相鄰設施最多攻擊一次。
- 設施受到的傷害為 `max(1, creature.attributes.armStrength - 2)`。
- 設施生命值歸零後從地圖移除。
- 移除時產生 Creature 行動紀錄。
- 被摧毀的設施不再阻擋路線，也不再提供視野或防禦效果。

### 7.3 建議第一版目標優先級

```text
玩家或資源點
→ 嘗試移動
→ 若路徑被防禦設施阻擋則攻擊相鄰設施
→ 巢穴或隨機巡邏
```

實際優先級應在加入防禦設施後重新進行戰鬥平衡測試。

## 9. 防禦設施詳情 modal

### 顯示規則

- 點擊地圖上的防禦設施 marker 開啟詳細資料 modal。
- 使用滑鼠點擊或鍵盤 `Enter`、`Space` 均可開啟。
- Creature 行動期間仍可查看資料，但不可執行後續維修或拆除操作。
- 建造位置選擇或攻擊目標選擇期間，設施 marker 不開啟詳情 modal，避免中斷目前操作流程。

### 顯示內容

- 名稱與圖示。
- 所屬據點。
- 位置。
- 生命值。
- 最大生命加成。
- 是否阻擋移動。
- 是否提供視野。
- 是否可維修。
- 建造成本。
- 箭塔的攻擊範圍與攻擊傷害。
- 設施目前狀態：運作中或已摧毀。

### 互動按鈕

- 查看詳細資料。
- 維修，若已完成修理系統。
- 拆除，若設計允許回收建料。

### 例外處理

- 非所屬玩家只能查看，不可維修或拆除。
- 設施已被摧毀時不再顯示互動按鈕。
- Creature 行動期間禁止操作。

## 10. 地形專屬防禦建築：五行五地形

> 本節新增「地形限制」機制：**通用設施**與**五行地形專屬設施**共存。
> 五行專屬設施僅能建在對應地形，並深度結合既有五行相剋與區域靈氣系統，解決遊戲後期防禦方式單調、變化不足的問題。

### 10.1 核心動機

- 讓不同地形的據點具備不同的防守「性格」，迫使玩家因地制宜規劃防禦。
- 與五行系統（巢穴主導元素、天地共鳴、相生相剋）結合，提供「剋制巢穴屬性」的主動工具。
- 部分專屬設施能壓制／淨化巢穴靈氣，較深層地與區域靈氣系統連動（見 `reports/system/regional-spiritual-energy-design.md`）。
- 保留通用設施，確保沒有對應地形的據點仍有基本防禦手段。

### 10.2 地形→五行→專屬設施 對應表

對應沿用天地共鳴關係（`terrainCombatRules.ts`），保持世界觀一致：

| 地形 | 元素 | 專屬設施 | 定位 |
| :--- | :--- | :--- | :--- |
| 草地（plain） | 土 | `earth-pillar` 地脈旗 | 防禦／輔助強化 |
| 森林（forest） | 木 | `wood-lodge` 樹靈祠 | 控制／衍生 |
| 水域（water） | 水 | `water-bastion` 水閘 | 控制／牽制 |
| 荒漠（desert） | 火 | `fire-beacon` 烽火台 | 傷害／範圍 |
| 山嶽（mountain） | 金 | `metal-shrine` 金煞罡壇 | 反傷／堅守 |

### 10.3 五行相剋應用

- 每個五行專屬設施擁有對應元素屬性。
- 當設施攻擊（或效果）瞄準的巢穴／生物屬性被其元素剋制時，效果獲得加成（復用 `skillRules.ts` 的 `getElementDamageMultiplier`）。
- 例如「金煞罡壇」（金）可剋制木屬性巢穴；建造時玩家可對照據點周遭巢穴屬性選擇利於剋制的設施。

### 10.4 與區域靈氣結合

- **壓制／淨化巢穴靈氣**：部分專屬設施在運作期間，能壓制其範圍內巢穴靈氣的負面效果（如烽火台壓制水屬性巢穴的潮濕靈氣）。
- **強化我方靈氣**：另一類設施類似「防衛營」，提供正面區域靈氣（如地脈旗強化範圍內玩家防禦）。
- 具體效果清單對齊 `auraRules.ts` 的 `AuraEffectKind`（damage-over-time / heal-over-time 等），避免另造一套系統。

### 10.5 五行地形專屬設施初步規格（草案）

> 以下為第一版數值草案，實際數值於實作前做平衡測試。

#### 地脈旗 `earth-pillar`（草地／土）

- 建料成本：20｜最大生命：90｜地形：草地
- 效果：範圍內玩家受到傷害 -10%（正面區域靈氣，`damage-reduction`）。
- 定位：草地據點的輔助強化核心。

#### 樹靈祠 `wood-lodge`（森林／木）

- 建料成本：20｜最大生命：90｜地形：森林
- 效果：周遭 3 格內生物定身（`immobilized`），每回合對範圍內一目標施放木系傷害。
- 定位：森林據點的控制型防禦。

#### 水閘 `water-bastion`（水域／水）

- 建料成本：25｜最大生命：100｜地形：水域
- 效果：範圍內生物移動消耗提高（緩速），並降低其命中。
- 定位：水域據點的牽制型防禦。

#### 烽火台 `fire-beacon`（荒漠／火）

- 建料成本：30｜最大生命：110｜地形：荒漠
- 效果：每回合對範圍內所有生物造成火系傷害（`damage-over-time`）並灼燒；可壓制水屬性巢穴靈氣。
- 定位：荒漠據點的範圍火力核心。

#### 金煞罡壇 `metal-shrine`（山嶽／金）

- 建料成本：25｜最大生命：120｜地形：山嶽
- 效果：反彈受到傷害（`reflectionPercent`），保護範圍內玩家與據點；金系剋制木屬性生物／巢穴。
- 定位：山嶽據點的堅守反傷核心。

### 10.7 對既有系統的影響與風險

- **建造範圍**：地形專屬設施需在據點建造範圍（基礎 6 格 + 官階加成）內恰有對應地形格才可建造；若某據點周遭缺乏該地形，則該專屬設施不可用，需靠通用設施補充。
- **Creature 互動**：所有設施（含專屬）皆以既有木柵規則處理：佔格、阻擋、可被攻擊、生命歸零移除（§7）。
- **主動效果時序**：專屬設施的週期效果（傷害／定身／緩速）在 Creature 回合結算點解析，對齊既有《區域靈氣/箭塔》的時序，避免新增第三種結算點。
- **平衡風險**：五行相剋加成與區域靈氣壓制可能大幅影響戰力，需在實作後監控各地形據點的防守難度落差。
- **後續工程**：需擴充 `DefenseStructureDefinition` 以支援 `element`、`activeEffect`、`terrainRequirements`（多地形）、以及在回合管線中解析專屬效果。

## 12. 測試與驗收

### 純函式測試

- 建造範圍（基礎 6 格 + 官階加成）內外判定，並驗證官階越高範圍越大。
- 牆體、水域與已佔用格判定。
- 建造範圍不超出據點上限（基礎 6 格 + 官階加成）。
- 設施成本與生命值正確。

### Action 測試

- 建料足夠時可建造。
- 建料不足時建造失敗且不扣建料。
- 玩家不在有效回合時建造失敗。
- 目標格被佔用時建造失敗。
- 建造成功後建料正確扣除。
- 建造結果確認後才結束回合。

### Creature 測試

- 木柵會阻擋 Creature 移動。
- Creature 可以攻擊設施。
- 設施 HP 歸零後從地圖移除。
- 設施移除後恢復通行。
- Creature 行動紀錄正確顯示。
- 瞭望塔與箭塔使用與木柵相同的阻擋與受擊規則。

### 驗收指令

```text
npm test
npm run lint
npm run build
```

## 13. 平衡風險

- 建料成本過低可能讓玩家塞滿據點周圍。
- 木柵永久阻擋會造成 Creature AI 無法尋路。
- 設施與城牆、瞭望塔等據點內建築效果可能重複。
- 防衛營增加氣血上限時不得同步恢復當前氣血，避免建築成為免費治療手段。
- 防衛營定位為據點周邊續戰力，不取代醫館、療傷藥或其他治療來源。
- 防衛營影響範圍使用曼哈頓距離 6 格。
- 玩家進入防衛營影響範圍時，最大氣血增加 50，當前氣血維持原值。
- 玩家離開影響範圍時移除加成；若當前氣血高於新上限，才限制到新上限。
- 醫館提供主動「就醫」互動；每次恢復氣血 10 點、內力 5 點，均受各自上限限制。
- 就醫不增加最大氣血、不修改角色根骨，也不會讓當前氣血超過上限。
- 建料倉庫提高所屬據點建料上限 `+50`。
- 建料倉庫使玩家從該據點所屬資源點採集時，額外獲得 `+5` 建料。
- 建料倉庫加成只影響主動採集，不影響資源點每回合被動收入。
- 建築功能採用宣告式 `actions` 與集中式 action registry；catalog 不直接保存執行函式。
- 修理工坊每恢復 1 點裝備耐久消耗 2 金錢。
- 點擊「修理」先開啟預覽，不立即扣除金錢；確認後才恢復所有裝備耐久、扣除金錢並結束回合。
- 修理預覽顯示裝備數量、恢復耐久總量與金錢消耗；沒有損耗裝備或金錢不足時不可執行。
- 本遊戲不使用獨立的防禦力數值；所有「防守能力」應轉換為最大生命、阻擋移動、視野或其他明確效果。
- 箭塔自動攻擊與玩家攻擊疊加後可能讓據點過於安全。
- 第一版每種設施只提供一個核心效果，避免系統過度複雜。
- 建議使用 Debug 地圖測試建造範圍、路線與資源消耗。

## 13.1 目前版本驗收範圍

- 本版本驗收「能否正確建造防禦設施」以及「Creature 能否正確與防禦設施互動」。
- 建造驗收必須包含：
  - 建造 modal 可開啟與關閉。
  - 三種設施可選擇，建料不足時正確 disabled。

  - 已佔用格、牆體與範圍外格不可建造。
  - 確認時重新驗證建料、玩家回合、據點與位置。
  - 建造成功後正確新增 marker、扣除建料並結束回合。

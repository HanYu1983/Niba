# 敵人巢穴動態屬性設計文件 (Enemy Nest Dynamic Attributes Design Document)

## 1. 文件目的

本文件旨在規劃遊戲中後期敵人巢穴的動態屬性變化機制，以增加遊戲挑戰性與策略深度。核心概念是讓巢穴擁有可變的主導元素，並以此影響其生成的怪物屬性、行為模式以及周圍的環境效果。

## 2. 設計目標

- **提升中後期遊戲挑戰性**：透過動態變化的敵人屬性，迫使玩家不斷調整戰術與裝備配置。
- **強化五行系統的策略深度**：讓五行相生相剋不僅體現在玩家自身功法搭配，也體現在與環境及敵人的互動上。
- **增加遊戲的可重玩性**：每次進入或面對不同狀態的巢穴時，都能帶來新的挑戰與體驗。
- **提供清晰的工程規格**：為開發團隊提供明確的設計方向與資料模型。

## 3. 核心機制：巢穴主導元素

### 3.1 巢穴類型與屬性
- **無屬性巢穴**：不具備任何五行元素屬性，其生成的怪物屬性將完全隨機，為玩家帶來不可預測的挑戰。
- **有屬性巢穴**：具備一個明確的五行主導元素（金、木、水、火、土），其生成的怪物將繼承或被該元素影響。

### 3.2 巢穴狀態資料模型

建議在巢穴的資料模型中新增以下欄位：

```ts
type NestState = {
  id: string;
  position: Position;
  // ... 其他現有巢穴屬性 ...

  dominantElement: ElementalAffinity; // 當前主導元素 (e.g., 'gold', 'wood', 'water', 'fire', 'earth')
  // ...
};

type ElementalAffinity = 'gold' | 'wood' | 'water' | 'fire' | 'earth';
```

## 4. 巢穴主導元素對遊戲的影響

### 4.1 影響怪物生成

- **怪物元素親和力**：
    - **無屬性巢穴**：生成的怪物將屬於中性或隨機的功法流派，玩家無法預測其具體戰鬥風格。
    - **有屬性巢穴**：生成的怪物將屬於與巢穴主導元素對應的功法流派。
        - **流派關聯**：例如，火焰巢穴生成赤炎流怪物，水之巢穴生成寒水流怪物。
        - **屬性影響**：這些怪物將繼承該流派的基礎屬性傾向與戰鬥風格。
- **怪物行為模式調整**：
    - **無屬性巢穴**：怪物行為模式隨機組合，增加玩家的應對難度。
    - **有屬性巢穴**：怪物行為模式將與其對應的功法流派相關聯。具體行為模式的詳細設計將留待後續階段，並依賴當前 AI 系統的實現。

### 4.2 影響環境效果

- **區域元素屬性**：巢穴周圍一定範圍內會產生與其主導元素相關的環境效果。這些效果的詳細機制請參閱 `reports/system/regional-spiritual-energy-design.md` 文件。
    - **火焰巢穴**：持續對範圍內玩家造成少量火焰傷害，或降低玩家的移動速度。
    - **水之巢穴**：範圍內玩家的移動速度大幅降低，或攻擊有一定機率被水流打斷。
    - **土之巢穴**：範圍內玩家的移動受阻，或防禦力提升。
    - **金之巢穴**：範圍內玩家的裝備耐久度下降更快，或受到持續傷害。
    - **木之巢穴**：範圍內玩家的生命恢復效果降低，或受到中毒效果。

### 4.3 影響玩家策略與五行互動

- **玩家內功/外功選擇**：玩家需要根據巢穴的主導元素，選擇能夠相生或相剋的內功與外功來應對。關於五行相生與相剋的詳細機制，請參閱 `reports/system/five-elements-generation-design.md` 文件。
    - **相生**：若玩家內功元素能生巢穴主導元素，玩家可能獲得額外增益（如傷害加成、抗性提升）。
    - **相剋**：若玩家內功元素能剋制巢穴主導元素，玩家可能獲得顯著優勢（如傷害大幅提升、敵人屬性大幅削弱）。
- **戰鬥結算調整**：戰鬥結算時，需要考慮巢穴的環境效果以及怪物與玩家的元素親和力/抗性。

## 5. 實施考量與後續步驟

- **文件關聯**：此設計將與現有的 `creature-system-design.md`、`five-elements-generation-design.md` 以及可能的 `nest-system-design.md` 文件緊密結合。
- **資料驅動**：巢穴的元素屬性、變異規則、怪物生成影響、環境效果等應盡可能資料化，方便調整與擴充。
- **UI 提示**：需要清晰的 UI 提示，讓玩家了解當前巢穴的主導元素及其帶來的影響。
- **平衡性測試**：動態屬性變化需要大量的平衡性測試，確保遊戲不會變得過於困難或過於簡單。

**後續步驟**：
1.  定義具體的元素循環與變異規則。
2.  細化各元素對怪物生成與行為的影響。
3.  設計各元素環境效果的具體數值與機制。
4.  更新怪物生成邏輯，使其能讀取並響應巢穴的主導元素。
5.  設計 UI 提示來展示巢穴的動態屬性。
6.  與戰鬥系統整合，確保元素相剋與環境效果正確作用。

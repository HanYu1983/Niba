## 一、概述

挑戰關卡提供一個「無限闖關」模式：玩家選擇一名名冊角色進入，每次通關後闖關等級 +1，地圖參數隨等級動態換算，難度遞增。

### 核心概念

```
全局共享闖關等級（所有角色共用）
  ↓
進入時用等級換算地圖參數
  ↓
通關 → 等級 +1
  ↓
下次進來更難
```

### 與現有模式的關係

| 模式 | 角色來源 | 持久化 | 殘卷結算 | 功法解鎖 |
|---|---|---|---|---|
| 沙盒模式 | 名冊角色 | 是 | 是 | 否 |
| 劇情模式 | 劇本定義 | 是 | 否 | 是（故事解鎖） |
| **挑戰關卡** | 名冊角色 | **是（闖關等級）** | **是** | **否** |

## 四、地圖參數換算規則

### 4.0 地圖設置選項總覽（以既有 `GameSettings` 為基準）

挑戰關卡的地圖參數全部由「單一輸入 `level`」換算。以下列出目前 `GameSettings`
（`src/game/types.ts` 型別、`src/game/gameSettings.ts` 預設值）的所有選項，
逐項討論它在挑戰關卡中「是否改變、如何換算」。

| 分類 | 欄位 | 預設值 | 說明 | 挑戰關卡處理 |
|---|---|---|---|---|
| **尺寸** | `rows` | 40 | 地圖行數 | 10 → 50，隨等級成長 |
| **尺寸** | `columns` | 40 | 地圖列數 | 10 → 50，隨等級成長 |
| **尺寸** | `seed` | 20260803 | 隨機種子 | 每次進入重抽（避免同圖）|
| **勢力** | `baseCount` | 5 | 我方基地數 | 由地圖面積換算 `max(1, floor(行×列/100))`|
| **勢力** | `playerCount` | 1 | 玩家數 | 固定 1（單人挑戰）|
| **勢力** | `aiPlayerCount` | 0 | AI 勢力數 | 固定 0（不開 PK）|
| **敵方** | `nestCount` | 2 | 敵方巢穴數 | 基地數 × 3 |
| **敵方** | `creatureCount` | 2 | 初始遊蕩怪數 | 基地數 × 10 |
| **據點** | `resourcePointCount` | 15 | 資源點數 | 基地數 × 3 |
| **據點** | `itemPointCount` | 8 | 道具點數 | 基地數 × 10（同遊蕩怪）|
| **據點** | `ruinCount` | 10 | 廢墟數 | 基地數 × 10（同遊蕩怪）|
| **據點** | `sectGateCount` | 3 | 中立門派據點（可重複）| 基地數 × 4 |
| **地形** | `terrainWeights` | plain 高 | 各地形生成權重 | 每次隨機（五種值域相同 rand(10,80)）|
| **探索** | `explorationEventCount` | 5 | 探索事件總數 | 基地數 × 10（同道具點）|
| **探索** | `explorationTriggerChance` | 0.2 | 回合結束觸發機率 | 固定 0.05 |
| **探索** | `nestHealthRegenPercent` | 0.01 | 巢穴每回合回血比 | 固定 0.01 |

> 本表為討論基準，各欄的「挑戰關卡處理」會逐項定案並更新。

### 4.1 換算原則

闖關等級作為單一輸入，換算以下地圖參數：

| 參數 | 換算方式 | 說明 |
|---|---|---|
| 地圖尺寸 | `10 + floor(level/2) × 2`，封頂 50 | 每 2 級 +2，Lv.40 達 50×50 |
| 基地數 | `max(1, floor(行×列 / 100))` | 每 100 格 1 座：10×10→1、20×20→4、50×50→25 |
| 巢穴數 | `基地數 × 3` | 每個基地 3 座敵方巢穴，攻防成對 |
| 初始遊蕩怪 | `基地數 × 10` | 開場即有的遊蕩怪，基地越多越難 |
| 資源點 | `基地數 × 3` | 資源點數跟隨基地數，供需成對 |
| 道具點 | `基地數 × 10` | 同遊蕩怪數，福利度隨難度同升 |
| 廢墟數 | `基地數 × 10` | 同遊蕩怪數，探索空間隨地圖擴大 |
| 門派據點 | `基地數 × 4` | 可重複，不封頂 |
| 怪物數量 | `3 + floor((level-1)/3)`，封頂 15 | 基礎數量 + 等級加成 |
| 地形權重 | 每次隨機（值域相同 rand(10,80)）| 五種地形各自隨機，值域相同 |
| 探索事件 | `基地數 × 10` | 同道具點數，地圖越大事件越豐富 |
| 探索觸發機率 | 固定 0.05 | 不隨等級變化 |
| 巢穴回血 | 固定 0.01 | 不隨等級變化 |

### 4.2 換算公式（已定案，無限關卡）

全部由單一輸入 `level` 換算，線性延伸、無上限。

#### 地圖尺寸 —— 線性成長，10×10 → 50×50 封頂

```ts
// 每 2 級成長 2 格（即每級 +1 行、+1 列），10 → 50
size = Math.min(10 + Math.floor(level / 2) * 2, 50)
rows = size
columns = size
```

| 等級 | 尺寸 | | 等級 | 尺寸 |
|---|---|---|---|---|
| Lv.1 | 10×10 | | Lv.20 | 30×30 |
| Lv.10 | 20×20 | | Lv.30 | 40×40 |
| Lv.15 | 24×24 | | Lv.40+ | 50×50（封頂）|

> **封頂原因**：地圖格數終有上限；Lv.40 後「尺寸固定、**屬性與 Boss 無限成長**」，
> 由屬性承載無限難度。地圖成長也讓後期的巢穴/怪物數量不必被格數卡死。

#### 基地數 —— 由地圖面積換算

```ts
// 基地數 = 地圖格數總數 / 100，向下取整，最少 1 座
baseCount = Math.max(1, Math.floor((rows * columns) / 100))
```

| 尺寸 | 面積 | 基地數 | | 尺寸 | 面積 | 基地數 |
|---|---|---|---|---|---|---|
| 10×10 | 100 | 1 | | 34×34 | 1156 | 11 |
| 12×12 | 144 | 1 | | 40×40 | 1600 | 16 |
| 20×20 | 400 | 4 | | 44×44 | 1936 | 19 |
| 24×24 | 576 | 5 | | 50×50 | 2500 | 25 |
| 30×30 | 900 | 9 | | | | |

> **原則**：基地數跟隨地圖**面積**（每 100 格 1 座、最少 1 座），地圖越大據點越多、
> 防守壓力分擔越廣，配合巢穴數成長讓攻防密度同步提升。

#### 巢穴數 —— 基地數 × 3

```ts
// 每 1 座基地對應 3 座敵方巢穴，攻防成對
nestCount = baseCount * 3
```

| 尺寸 | 基地數 | 巢穴數 | | 尺寸 | 基地數 | 巢穴数 |
|---|---|---|---|---|---|---|
| 10×10 | 1 | 3 | | 34×34 | 11 | 33 |
| 12×12 | 1 | 3 | | 40×40 | 16 | 48 |
| 20×20 | 4 | 12 | | 44×44 | 19 | 57 |
| 24×24 | 5 | 15 | | 50×50 | 25 | 75 |
| 30×30 | 9 | 27 | | | | |

> **原則**：基地數由面積決定，每座基地配置 3 座敵方巢穴——
> 地圖越大攻防密度同步提升，避免巢穴無限成長到塞不下地圖。

#### 初始遊蕩怪 —— 基地數 × 10

```ts
// 開場即有的大量遊蕩怪，基地越多難度越高
creatureCount = baseCount * 10
```

| 尺寸 | 基地數 | 遊蕩怪 | | 尺寸 | 基地數 | 遊蕩怪 |
|---|---|---|---|---|---|---|
| 10×10 | 1 | 10 | | 34×34 | 11 | 110 |
| 12×12 | 1 | 10 | | 40×40 | 16 | 160 |
| 20×20 | 4 | 40 | | 44×44 | 19 | 190 |
| 24×24 | 5 | 50 | | 50×50 | 25 | 250 |
| 30×30 | 9 | 90 | | | | |

> **原則**：初始遊蕩怪數跟隨基地數——基地越多，開場即遇大量怪物，
> 加上巢穴持續產兵，形成層層壓迫的攻勢。

#### 資源點 —— 基地數 × 3

```ts
// 資源點數跟隨基地數，每座基地 3 個資源點
resourcePointCount = baseCount * 3
```

| 尺寸 | 基地數 | 資源點 | | 尺寸 | 基地數 | 資源點 |
|---|---|---|---|---|---|---|
| 10×10 | 1 | 3 | | 34×34 | 11 | 33 |
| 12×12 | 1 | 3 | | 40×40 | 16 | 48 |
| 20×20 | 4 | 12 | | 44×44 | 19 | 57 |
| 24×24 | 5 | 15 | | 50×50 | 25 | 75 |
| 30×30 | 9 | 27 | | | | |

> **原則**：資源點數跟隨基地數——多據點就需要更多資源供給，
> 維持「難度 − 福利 ≈ 恆定」的平衡哲學。

#### 道具點／廢墟 —— 基地數 × 10（同遊蕩怪）

```ts
// 道具點與廢墟數皆等同開場遊蕩怪數，隨基地數同比例成長
itemPointCount = baseCount * 10
ruinCount = baseCount * 10
```

| 尺寸 | 基地數 | 道具點／廢墟 | | 尺寸 | 基地數 | 道具點／廢墟 |
|---|---|---|---|---|---|---|
| 10×10 | 1 | 10 | | 34×34 | 11 | 110 |
| 12×12 | 1 | 10 | | 40×40 | 16 | 160 |
| 20×20 | 4 | 40 | | 44×44 | 19 | 190 |
| 24×24 | 5 | 50 | | 50×50 | 25 | 250 |
| 30×30 | 9 | 90 | | | | |

> **原則**：道具點與廢墟數跟隨基地數——地圖越大探索資源越豐富，
> 福利度（道具/廢墟/資源）與難度（巢穴/遊蕩怪）同步成長，維持平衡。

#### 門派據點 —— 基地數 × 4

```ts
// 門派據點可重複，不封頂，隨基地數成比例成長
sectGateCount = baseCount * 4
```

| 尺寸 | 基地數 | 門派據點 | | 尺寸 | 基地數 | 門派據點 |
|---|---|---|---|---|---|---|
| 10×10 | 1 | 4 | | 34×34 | 11 | 44 |
| 12×12 | 1 | 4 | | 40×40 | 16 | 64 |
| 20×20 | 4 | 16 | | 44×44 | 19 | 76 |
| 24×24 | 5 | 20 | | 50×50 | 25 | 100 |
| 30×30 | 9 | 36 | | | | |

> **原則**：門派據點可重複（同門派多個據點），不設封頂，
> 跟隨基地數成比例成長——地圖越大中立據點越密集。

#### 怪物數量 —— 線性成長，隨尺寸封頂

```ts
enemyCount = 3 + Math.floor((level - 1) / 3)   // 每 3 級 +1
enemyCount = Math.min(enemyCount, 15)          // 隨地圖成長至 50×50 可容納更多
```

#### 地形權重 —— 五種地形值域相同，各自隨機

```ts
// 每種地形各自獨立隨機，但五者的值域（範圍）完全相同
terrainWeights = {
  plain:    rand(10, 80),
  forest:   rand(10, 80),
  water:    rand(10, 80),
  mountain: rand(10, 80),
  desert:   rand(10, 80),
}
```

> **原則**：五種地形**值域完全相同**（皆 `rand(10, 80)`），但各自獨立隨機取值——\n> 每種地形對地圖密度的影響潛力相等、公平，但實際生成仍因隨機而多變，\n> 不隨等級變化（難度主要由其他參數保證）。

#### 探索事件 —— 基地數 × 10（同道具點）

```ts
// 探索事件總數等同道具點數，隨基地數同比例成長
// 觸發機率固定 0.05，不隨等級變化
explorationEventCount = baseCount * 10
explorationTriggerChance = 0.05
```

| 尺寸 | 基地數 | 探索事件 | | 尺寸 | 基地數 | 探索事件 |
|---|---|---|---|---|---|---|
| 10×10 | 1 | 10 | | 34×34 | 11 | 110 |
| 12×12 | 1 | 10 | | 40×40 | 16 | 160 |
| 20×20 | 4 | 40 | | 44×44 | 19 | 190 |
| 24×24 | 5 | 50 | | 50×50 | 25 | 250 |
| 30×30 | 9 | 90 | | | | |

> **原則**：探索事件總數等同道具點數——地圖越大事件越豐富，
> 保持隨機探索的樂趣與福利度，與難度同步成長。

| 等級 | 怪物數 | | 等級 | 怪物數 |
|---|---|---|---|---|
| Lv.1 | 3 | | Lv.25 | 11 |
| Lv.4 | 4 | | Lv.28 | 12 |
| Lv.7 | 5 | | Lv.31 | 13 |
| Lv.10 | 6 | | Lv.34 | 14 |
| Lv.20 | 9 | | Lv.37+ | 15（封頂）|

> **封頂原因**：怪物數量受地圖格數與巢穴佈局限制；
> 由於尺寸會成長至 50×50，數量上限放寬到 15，封頂落在 Lv.37。

> **備註**：怪物數量以外的生物數值（怪物等級、怪物屬性、Boss、掉落）皆不屬於地圖設置\n> `GameSettings` 的參數——它們由生物 / 巢穴 / 結算生成邏輯決定，\n> 因此在挑戰關卡的**地圖設置換算中不列怪物等級、怪物屬性、Boss、掉落項**。\n\n#### 結束：地圖設置換算項目完畢

### 4.3 換算函式簽章

```ts
// src/game/challengeMapGenerator.ts — 新檔案

/** 挑戰關卡的地圖配置。 */
export type ChallengeMapConfig = {
  rows: number                  // 10 + floor(level/2)*2，封頂 50
  columns: number               // 同上（方形）
  baseCount: number             // max(1, floor(rows*columns/100))：每 100 格 1 座（最多 25）
  nestCount: number             // baseCount * 3：每基地 3 巢（最多 75）
  creatureCount: number         // baseCount * 10：開場遊蕩怪（最多 250）
  resourcePointCount: number    // baseCount * 3：資源點（最多 75）
  itemPointCount: number        // baseCount * 10：道具點（最多 250）
  ruinCount: number             // baseCount * 10：廢墟（最多 250）
  sectGateCount: number         // baseCount * 4：門派據點（可重複，不封頂）
  enemyCount: number            // 3 + floor((level-1)/3)，封頂 15
  terrainWeights: TerrainWeights // 五種地形各 rand(10,80)，值域相同
  explorationEventCount: number // baseCount * 10：探索事件（最多 250）
  explorationTriggerChance: number // 固定 0.05
  nestHealthRegenPercent: number   // 固定 0.01
}

/**
 * 依闖關等級換算地圖配置。
 * @param level 闖關等級（≥1）
 * @returns 換算後的地图配置
 */
export function generateChallengeMapConfig(level: number): ChallengeMapConfig
```

## 五、遊戲流程

### 5.1 進入挑戰關卡

```
1. 玩家點擊「挑戰關卡」Tab
2. 顯示當前闖關等級、歷史最高、總通關次數
3. 玩家選擇要使用的名冊角色
4. 顯示預估關卡資訊（地圖尺寸、基地/巢穴/怪物數量、地形權重等）
5. 點擊「開始挑戰」→ 呼叫 generateChallengeMapConfig(level)
6. 生成 GameState（使用換算後的參數）
7. 進入戰鬥
```

### 5.2 通關處理

```
1. 擊敗所有敵人（含 Boss）
2. 記錄勝利：recordChallengeVictory()
   → level +1, highestLevel = max(highestLevel, newLevel), totalClears +1
3. 殘卷結算：applyEndGameRewards(角色 id, stats, won=true, gainedSkillIds)
   → 殘卷 = 6 + level × 2（勝）
4. 顯示通關畫面
5. 選項：[繼續挑戰]（直接下一關）或 [返回主選單]
```

### 5.3 失敗處理

```
1. 玩家陣亡或觸發失敗條件
2. 不扣任何東西（無懲罰）
3. 顯示失敗畫面
4. 選項：[重新挑戰]（同等級重來）或 [返回主選單]
```

### 5.4 讀檔相容

- 舊版 localStorage 沒有 `mygame2.challenge-state` → 初始化為 `{ level: 1, highestLevel: 0, totalClears: 0 }`
- 不影響既有資料

## 六、與現有系統的整合點

### 6.1 角色選擇

- 共用名冊角色（`getCharacters()`）
- 進入時複製角色狀態（不修改原角色）
- 結束後帶回原狀態（殘卷已寫入）

### 6.2 殘卷結算

- 共用 `applyEndGameRewards()`
- 勝利殘卷公式：`6 + level × 2`（勝）、`3 + level × 1`（敗）
- 可調參數，待定

### 6.3 地圖生成

- 共用 `createRoamerCreatures()` 或巢穴生成邏輯
- 差異在於傳入的 `level` 參數不同
- 需要一個 wrapper 函式把換算結果餵給既有生成器

### 6.4 通關紀錄

- 獨立於劇情通關（`campaignClearance.ts`）
- 不影響任何劇情解鎖（挑戰關卡不是劇情模式）

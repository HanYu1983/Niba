## 1. 系統範圍與核心概念

### 1.1 文件目的

- 定義「地圖防禦設施」的資料模型、建造流程、Creature 互動與各設施效果。
- 與據點內建築（Base Buildings）清楚區分。
- 記錄目前代碼狀態，作為後續擴充（五行地形專屬設施、官階範圍增長等）的基準。

### 1.2 核心設計哲學

防禦設施是「佔用地圖格子的實體物件」，而非單純的據點數值加成：

```text
資源點
→ 產出建料
→ 據點消耗建料建造防禦設施
→ 防禦設施改變地圖路線、視野或提供自動攻擊
→ Creature 攻擊設施並造成損耗
→ 玩家選擇維修、替換或放棄設施（維修／拆除尚未實作）
```

### 1.3 與據點內建築的區分

| 維度 | 據點內建築 | 地圖防禦設施 |
| :--- | :--- | :--- |
| 位置 | 據點內部 | 地圖格子 |
| 佔格 | 不佔世界格 | 佔用地圖格（道路除外） |
| 資料結構 | `BaseState.buildings` | `GameState.defenseStructures` |
| 管理目錄 | `buildingCatalog` | `defenseStructureCatalog` |

## 3. 資料模型與建造目錄（實際代碼）

### 3.1 防禦設施型別

```ts
type DefenseStructureType =
  // 據點可建造
  | 'barricade' | 'strong-barricade'
  | 'watchtower' | 'advanced-watchtower'
  | 'arrow-tower' | 'advanced-arrow-tower' | 'road'
  // 廢墟修復產生（不透過據點建造）
  | 'small-watchtower' | 'small-arrow-tower' | 'small-waystation'
```

### 3.2 建造目錄定義

```ts
type DefenseStructureDefinition = {
  type: DefenseStructureType
  name: string
  description: string
  icon: string
  constructionCost: number
  /** 建造所需官階；廢墟小型設施為 0。 */
  requiredRank: number
  maxHealth: number
  healthBonus: number
  blocksMovement: boolean
  providesVision: boolean
  attackRange: number
  attackDamage: number
  /** 道路等不佔格子的設施：建造時改寫地形，而非新增防禦設施。 */
  changesTerrain?: boolean
}
```

### 3.3 建造目錄內容（實際數值）

> 目前全部為**通用建築，不限地形**。地形限制欄位（`terrainRequirements`）尚未啟用，保留為未來的五行地形專屬設施預留（見 §8.2）。

| `road` | 道路 | 5 | 1 | 0 | 無（通用） | ❌ | ❌ | 0 | 0 | 改地形為道路 |

### 3.4 可建造目錄

```ts
/** 玩家可透過據點建造的防禦設施（排除廢墟專屬的小型設施）。 */
buildableDefenseStructureCatalog = defenseStructureCatalog.filter(
  (d) => d.type !== 'small-watchtower' && d.type !== 'small-arrow-tower' && d.type !== 'small-waystation',
)
```

> **通用性**：目前所有據點可建造的設施皆不限地形，任何地形的空格皆可建造（只要不在牆上、未被佔用）。地形限制（`terrainRequirements`）鍵僅為未來五行地形專屬設施保留（§8.2）。

### 3.5.1 各設施效果詳細說明

#### 地脈旗 `earth-pillar`（草地／土）

- **核心效果**：產生正面區域靈氣，強化範圍內玩家的防禦能力。
- **靈氣類型**：`damage-reduction`（減傷）。
- **效果數值**：範圍內玩家受到傷害 -10%。
- **範圍**：以設施為中心，半徑 3 格（曼哈頓距離）。
- **疊加**：多座地脈旗的減傷可疊加（乘法），但需注意平衡上限。
- **與五行**：土系；剋制水系巢穴／生物。
- **設計動機**：讓草地據點成為「銅牆鐵壁」型的防守核心，適合龜縮防守。

#### 樹靈祠 `wood-lodge`（森林／木）

- **核心效果**：控制型防禦，對範圍內生物有機率定身，並對單一目標施放木系傷害。
- **靈氣類型**：`immobilized`（定身，機率觸發）＋木系單體傷害。
- **效果數值**：
  - 每回合**有一定機率（建議 40%）**對範圍內生物施加定身（`immobilized`，跳過移動），而非確保，避免踏入範圍即癱瘓全場。
  - 每回合對範圍內 1 名目標施展木系傷害（基礎 10）。
- **平衡考量**：
  - 定身採「機率」而非「每回合確保」，讓生物仍有機會行動或逃離，保留走位與對抗空間。
  - 若生物離開範圍，定身依位置即時解除（對齊既有區域靈氣生命週期）。
  - 實際機率（建議 40%）於平衡測試時調整。
- **範圍**：以設施為中心，半徑 3 格（曼哈頓距離）。
- **與五行**：木系；剋制土系巢穴／生物。
- **設計動機**：森林據點以「遲滯敵軍 + 持續消耗」為主，將敵人困在森林主場，但保留克制空間。

#### 水閘 `water-bastion`（水域／水）

- **核心效果**：牽制型防禦，緩速範圍內生物，並提高範圍內玩家的回避率。
- **靈氣類型**：`movement-cost`（移動消耗提高）＋`evasion-rate-bonus`（回避率提高）。
- **效果數值**：
  - 範圍內生物移動消耗提升（每格 +1）。
  - 範圍內玩家回避率提高（+5%），讓水域據點內的己方更難被命中。
- **範圍**：以設施為中心，半徑 4 格（曼哈頓距離）。
- **與五行**：水系；剋制火系巢穴／生物。
- **設計動機**：水域據點擅長「以拖延換取時間」＋「閃避自保」，讓敵人難以接近據點核心，同時保護範圍內的己方玩家。

#### 烽火台 `fire-beacon`（荒漠／火）

- **核心效果**：範圍火力核心，對範圍內所有生物造成火系傷害並灼燒。
- **靈氣類型**：`damage-over-time`（灼燒）。
- **效果數值**：
  - 每回合對範圍內所有生物造成火系傷害（基礎 8）。
  - 成功命中後施加 `scarlet-flame-burning`（燃燒）Buff。
- **範圍**：以設施為中心，半徑 3 格（曼哈頓距離）。
- **與五行**：火系；剋制金系巢穴／生物。
- **設計動機**：荒漠據點以「高範圍輸出」壓制敵軍，是主要的傷害型防禦設施。

> **備註**：暫不規劃「壓制巢穴區域靈氣」等與巢穴靈氣互動的特殊能力，因巢穴區域靈氣系統尚未完整設計（見《區域靈氣》文件），待該系統完成後再評估。

#### 金煞罡壇 `metal-shrine`（山嶽／金）

- **核心效果**：堅守反傷，保護範圍內玩家與據點。
- **靈氣類型**：`reflection`（反彈傷害）。
- **效果數值**：
  - 範圍內玩家受到傷害時，反彈部分傷害給攻擊者（反射比例待定案，建議 25%）。
  - 依據點受擊時，同樣反彈部分傷害。
- **範圍**：以設施為中心，半徑 3 格（曼哈頓距離）。
- **與五行**：金系；剋制木系巢穴／生物。
- **設計動機**：山嶽據點為「易守難攻」的代表，依靠反傷懲罰來犯之敵。

> **共通效果模型**：以上設施效果的「靈氣」皆對齊 `auraRules.ts` 的 `AuraEffectKind`（damage-reduction / damage-over-time / movement-cost / reflection / immobilized 等），不另造一套系統；五行相剋復用 `skillRules.ts` 的 `getElementDamageMultiplier`。**效果數值為草案，實作前需平衡測試。**

### 3.6 後期通用型防禦建築（規劃草案，尚未實作）

> 本節為**後期旗艦設施**：高官階解鎖、高建料成本、不限地形（通用），效果**大幅改變戰局走向**而非堆疊數值。
> 每一座設施具單一「戰局級」效果，定位分明，避免疊加失衡。

| type（規劃） | 名稱 | 成本 | 官階 | 生命 | 類別 | 效果定位 |
| :--- | :--- | ---: | ---: | ---: | :--- | :--- |
| `warcamp-bastion` | 軍壘 | 150 | 4 | 100 | 據點強化 | 強化自身 3 格內箭塔／瞭望塔系列（HP ×2、箭塔攻擊 ×2） |
| `bombard-cannon` | 轟城砲 | 200 | 5 | 180 | 範圍大殺器 | 超遠距範圍砲擊 |
| `supply-depot` | 輜重庫 | 120 | 3 | 160 | 資源經濟 | 建造大型資源點（採集量 ×3） |
| `warning-beacon` | 烽燧臺 | 100 | 6 | 140 | 全局支援 | 全圖揭示敵軍動向 |

#### 軍壘 `warcamp-bastion`（據點強化）

- **核心效果**：強化**軍壘自身 3 格範圍內**的箭塔、大型箭塔、瞭望塔與大型瞭望塔，使其火力／耐久大幅提升。
- **效果類型**：範圍內防禦設施強化（箭塔／大型箭塔／瞭望塔／大型瞭望塔）。
- **數值草案**：
  - 以軍壘為中心，**半徑 3 格（曼哈頓距離）**內的所有箭塔／瞭望塔系列設施獲得強化。
  - **箭塔、大型箭塔**：**HP ×2**、**攻擊力 ×2**。
  - **瞭望塔、大型瞭望塔**：**HP ×2**（無攻擊力，故不適用攻擊強化）。
  - **建造完成的瞬間**，軍壘 3 格範圍內的所有箭塔／瞭望塔系列設施**回復所有 HP**。
  - 範圍外不受影響；軍壘被摧毀後，強化效果立即消失（設施回復原數值）。
- **定位**：讓玩家以一座軍壘在指定防線範圍提升塔類設施火力與耐久，並在建造當下重置範圍內塔類設施耐久，是後期「局部塔防樞紐」型的據點強化設施。

#### 轟城砲 `bombard-cannon`（範圍大殺器）

- **核心效果**：超遠距、大範圍砲擊，可打擊據點範圍外的敵軍集中區域。
- **效果類型**：範圍傷害（`damage-over-time` 瞬間爆發）。
- **數值草案**：
  - 射程極遠（如半徑 8-10 格），範圍內所有生物受到高額傷害。
  - 有冷卻（每 N 回合可發射一次）。
- **定位**：後期反制敵軍集結與巢穴增援，一擊改寫野戰局面。

#### 輜重庫 `supply-depot`（資源經濟）

- **核心效果**：建造一座「大型資源點」——與一般資源點功能完全相同，但**資源採集量 ×3**。
- **效果類型**：資源點（`ResourcePointState`）。
- **數值草案**：
  - 建造後於輜重庫位置生成一座大型資源點，歸屬所屬據點。
  - 功能與 `ResourcePointState`（資源點）一致：玩家可採集、每回合被動建料收入、可被 Creature 攻擊等。
  - **採集量為一般資源點的 3 倍**（`materialIncome` ×3）。
- **定位**：後期為據點提供一座高產資源點，顯著提升建料來源，支撐長期戰線與大型建設。

#### 烽燧臺 `warning-beacon`（全局支援）

- **核心效果**：全局揭示範圍外敵軍動向，預警敵軍集結／攻擊路線。
- **效果類型**：情報（全圖敵軍揭示）＋預警。
- **數值草案**：
  - 每回合揭示地圖上所有生物的動向（或指定距離內）。
  - 生物接近我方據點時觸發警示。
- **定位**：後期掌握全局敵情，決定調度與防守優先級，是情報戰的核心。

> **共通原則**：以上後期設施同樣不限地形、可疊加數值但有清晰定位；多數支援「改變戰局」的戰術價值，而非單純傷害／生命數字。**皆為草案，實作前需平衡測試。**

## 4. 建造規則

### 4.1 建造範圍

> **目前代碼**：固定 5 格曼哈頓距離（`defenseRules.ts` 的 `distance > 5`）。**未有官階加成**。

```ts
const distance =
  Math.abs(base.row - target.row) + Math.abs(base.column - target.column)
const canBuildInRange = distance <= 5
```

> **規劃**（未實作）：建造範圍隨據點所屬玩家官階增長——官階每高 1 級 +1，官階 6 總共 +5，最大 11 格。此為設計目標，代碼尚未實作。

### 4.2 建造驗證（`validateDefenseBuild`）

建造需通過以下檢查（依序）：

1. 玩家存在且為目前行動玩家。
2. 據點與設施定義存在。
3. **官階**：玩家官階 ≥ 設施 `requiredRank`。
4. 不在 Creature 行動期間。
5. 玩家位於據點旁（相鄰）。
6. 建料充足。
7. 目標格非牆體。
8. 目標格在據點 5 格範圍內。
9. 非道路設施不得建在已佔用格（道路可建在被佔用格，但不可建在牆上）。

### 4.3 建造成本與行動

- 建造消耗建料（`definition.constructionCost`）與體力。
- 道路類設施（`changesTerrain`）使用不同體力成本（`ACTION_STAMINA_COSTS.roadBuild`），並改寫地形。
- 建造成功後結束玩家回合。
- 劇情模式下，建造會推進 `build-defense-structure` 目標並檢查勝利。

### 4.4 建造流程（Stage）

1. **開啟防禦建設**：據點詳情點擊「防禦建設」（`operation = building-defense`）。
2. **選擇設施**：顯示設施清單、建料、建造範圍、官階需求；建料或官階不足時 disabled。
3. **選擇位置**：依所選設施的範圍與地形過濾高亮可建造格。
4. **確認建造**：再次驗證建料、官階、範圍、位置、玩家回合。
5. **結果確認**：彈窗確認後結束回合。

## 5. 與 Creature 互動

> 所有防禦設施採用相同核心規則：佔格、阻擋移動、可被攻擊、生命歸零移除。

### 5.1 移動阻擋

- 所有 `blocksMovement` 的設施（含小型瞭望臺／箭塔／驛站）加入 Creature 尋路阻擋。
- Creature 無法進入或穿越施設所在格。
- 道路不阻擋（`changesTerrain` 改地形，不新增實體）。

### 5.2 阻路攻擊

- Creature 在無法到達目標時，會**找出實際堵住最佳去路的設施**（`findBlockingDefenseId`）並攻擊該座；只有被擋下時才反擊該座，不會為了遠方設施偏離目前目標。

### 5.3 攻擊傷害

- 設施受到的傷害為 `max(1, creature.attributes.armStrength - 2)`。
- 生命歸零後從地圖移除。
- 若設施由廢墟修復而成（`originName`），連同對應已修復的廢墟一併移除。

### 5.4 目標優先級

```text
玩家或資源點
→ 嘗試移動
→ 若路徑被防禦設施阻擋則攻擊相鄰設施
→ 巢穴或隨機巡邏
```

## 6. 防禦設施效果

### 6.1 箭塔自動攻擊

- 在 `creatureTurnPipeline` 中，對所有 `arrow-tower` / `advanced-arrow-tower` / `small-arrow-tower` 依其 `attackRange` 選取射程內目標並造成 `attackDamage`。
- 被擊敗的生物自該回合後續移動與攻擊流程排除。

### 6.2 瞭望塔視野

- `watchtower` 提供 3 格視野。
- `advanced-watchtower` 提供 5 格視野。
- `small-watchtower` 提供 2 格視野。

> 詳細迷霧規則見 [`fog-of-war-design.md`](fog-of-war-design.md)。

### 6.3 道路

- 建造時將目標格地形改為 `road`，移動阻力降為 1（`changesTerrain`）。
- 不佔格、不產生實體防禦單位、不算防禦設施數量。

### 6.4 廢墟修復

- 廢墟可選擇修復為：
  - `small-watchtower`（小型瞭望臺，視野 2 格＋阻擋）
  - `small-arrow-tower`（小型箭塔，射程 1 格、傷害 5、視野 1 格＋阻擋）
  - `small-waystation`（小型驛站，提供傳送＋阻擋）
- 修復後設施具 `originName`，被摧毀時連同對應廢墟移除。
- 小型設施 `constructionCost`／`requiredRank` 為 0（不透過據點建造）。

## 10. 開發注意事項（依目前代碼實作）

> 本節針對本次新增／規劃設施（堅壘、軍壘、轟城砲、輜重庫、烽燧臺、五行地形專屬設施）記錄**實作時的關鍵陷阱與既有代碼錨點**。

### 10.1 資料模型擴充

- `DefenseStructureType` 目前定義於 `src/game/catalogs/defenseStructureCatalog.ts`，新增設施時需在此 union 增加 type。
- `DefenseStructureDefinition` 已含 `requiredRank`，但**無 `element`、`activeEffect`、`terrainRequirements` 欄位**。五行／後期設施若需五行相剋或區域靈氣，須先擴充此型別。
- 道路設施用 `changesTerrain?: boolean` 標記「不佔格、改地形」；若將來有其他「非實體」設施，可沿用此模式。

### 10.2 建造流程與驗證

- 建造核心在 `buildingActions.ts` 的 `constructDefenseStructure` + `defenseRules.ts` 的 `validateDefenseBuild`。
- `validateDefenseBuild` 目前**硬編碼 `distance > 5`**（固定 5 格），尚無官階加成——實作 §4.1「官階增長」需改此處，用 `getGovernanceRank(player.prestige).rank` 計算加成為 `5 + (rank - 1)`。
- 新建設施需在 `defenseStructureCatalog` 加入完整定義，否則 `validateDefenseBuild` 找不到 definition 會回傳「據點或設施不存在」。

### 10.3 Creature 回合效果掛載點

- 箭塔自動攻擊邏輯在 `creatureTurnPipeline.ts` 的 `runCreatureTurn` 內，依 `structure.type` 過濾 `arrow-tower` / `advanced-arrow-tower` / `small-arrow-tower`。
- **轟城砲、烽火台、五行設施的「每回合效果」應掛在此管線**，與箭塔同一結算時序，避免新增第三種結算點。
- 烽火台「每回合 50% 機率揭示全圖敵人」與現有「鳴鑼符（reveal-creatures）」機制一致：設置 `state.revealedCreatureCellIds` + `state.revealedCreatureUntilRound = round + 1`（見 `gameStore.ts` 的鳴鑼符分支與 `visibilityRules.ts` 的 `getCellVisibility`）。烽火台可復用此欄位，不需另作視野系統。

### 10.4 據點強化（軍壘）時序

- 軍壘「強化 3 格內箭塔／瞭望塔」是非持久性數值飛場（HP ×2、攻擊 ×2），**不應直接改寫 `DefenseStructureState` 的 `health`/`maxHealth` 永久值**，否則軍壘被摧毀後難以還原。
- 建議：在箭塔攻擊結算與 HP 檢視時，動態查詢「該箭塔是否位於某活躍軍壘 3 格內」來套用 ×2 乘算；軍壘失活即自動失效，避免維護還原狀態。
- 「建造瞬間回復範圍內塔類 HP」需在 `constructDefenseStructure` 完成後，掃描範圍內設施並 `health = maxHealth`（一次觸發，非每回合）。

### 10.5 大型資源點（輜重庫）

- 資源點模型為 `ResourcePointState`，`materialIncome` 為採集量；一般資源點 base 值為 15（見 `worldGeneration.ts` 的 `createResourcePoints`）。
- 「大型資源點」直接建立一枚 `ResourcePointState`，`materialIncome = 15 × 3 = 45` 即可，完全復用既有採集／被動收入／被攻擊機制。
- **注意**：輜重庫是「防禦設施」但產出的是 `resourcePoints` 陣列中的資源點，需額外在 GameState 中將該資源點加入 `state.resourcePoints`，而非只加 `defenseStructures`（兩者資料結構不同，見 `types.ts`）。
- 被動收入在 `turnActions.ts` 的 `endPlayerTurn` 中依 `ownerBaseId` 聚合 `materialIncome`，新的高產資源點會自動納入。

### 10.6 視野（瞭望塔系列）與烽燧台

- 視野計算在 `visibilityRules.ts` 的 `getPlayerVisibleCellIds`，已對 `watchtower` / `advanced-watchtower` / `small-watchtower` / `small-arrow-tower` 各自套用固定視野範圍常數。
- 堅壘／軍壘不提供視野，無需在此處理；烽火台「揭示全部敵人」走 `revealedCreatureCellIds` 而非視野，兩者不混淆。

### 10.7 五行地形專屬設施（§8.2）

- 需先在 `DefenseStructureDefinition` 增加 `terrainRequirements?: TerrainType[]` 並在 `validateDefenseBuild` 加地形檢查（目標格地形 ∈ requirements）。
- 五行相剋傷害可復用 `skillRules.ts` 的 `getElementDamageMultiplier`；區域靈氣效果需擴充 `auraRules.ts` 的 `AuraEffectKind`（目前僅 `damage-over-time` / `heal-over-time`，缺 `evasion-rate-bonus`、`movement-cost`、`reflection`、`immobilized` 等，需先補上）。
- 水閘／樹靈祠／金煞罡壇等被動靈氣效果，時序上對齊 `resolveRoundEndAuraEffects`（每回合累積型）或即時查詢（被動型），並遵從「來源失活即失效」。

### 10.8 建造官階增長（§4.1）

- 官階函式 `getGovernanceRank(player.prestige).rank`（`governanceRules.ts`），`maxBuildingLevel` 已用於據點內建築限制，可參考其用法。
- 建造範圍改成動態後，`MapGrid` 的建造高亮（`defenseBuildMode`）需同步以 `buildRange` 過濾，而非寫死 5。

### 10.9 測試注意

- 新增設施需補 `defenseStructureCatalog` 定義測試、`validateDefenseBuild` 官階/地形/佔位測試。
- 軍壘強化、轟城砲、烽燧台等週期效果需在 `creatureTurnPipeline` 或回合結算測試中驗證，確保多設施疊加與失效邏輯正確。

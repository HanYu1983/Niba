# 戰爭迷霧開發設計文件

## 1. 文件目的

- 在現有地圖、回合、Creature、據點與探索框架上加入戰爭迷霧。
- 讓玩家透過移動、據點建設與情報逐步取得地圖資訊。
- 先完成可驗證的 MVP，不立即加入複雜視線遮擋與多人視野同步。

## 2. 設計目標

### 2.1 核心體驗

- 未知區域需要探索，不在遊戲開始時完整揭露所有功能標記。
- 玩家移動會逐步擴張已知區域。
- Creature 與巢穴在視野外不提供即時位置與狀態。
- 玩家需要在探索收益與遭遇風險間做選擇。

### 2.2 與現有系統的關聯

- **地圖**：依格子保存探索與可見狀態。
- **移動**：移動成功後更新視野。
- **Creature**：視野外不顯示，也不可被攻擊。
- **巢穴**：可記住已發現位置，但視野外不顯示即時血量；MVP 可先完全隱藏。
- **資源點/道具點**：未探索前隱藏，發現後依規則保留位置。
- **據點/建築**：地圖防禦設施 `watchtower`「瞭望塔」可提供額外視野範圍；目前沒有據點內瞭望塔或指揮塔。
- **事件/寶箱/NPC**：未來沿用同一套可見性規則。

## 3. 可見性資料模型

### 3.1 格子狀態

```ts
type VisibilityState = 'unexplored' | 'explored' | 'visible'
```

- `unexplored`：玩家從未看過。
- `explored`：玩家曾經看過，但目前不在視野內。
- `visible`：目前位於玩家視野內。

### 3.2 GameState 建議欄位

單人 MVP：

```ts
type VisibilityStateData = {
  exploredCellIds: string[]
  mode: 'fog' | 'revealed'
}
```

未來多人：

```ts
type PlayerVisibilityState = {
  playerId: string
  exploredCellIds: string[]
}
```

### 3.3 Debug 模式

- 正式地圖：`mode: 'fog'`。
- Debug 地圖：`mode: 'fog'`，與正式地圖使用相同戰爭迷霧規則。
- `revealed` 僅保留為未來特殊測試或開發工具模式，不作為目前 Debug 地圖預設值。

## 4. MVP 視野規則

### 4.1 視野距離

第一版使用曼哈頓距離，不加入牆體視線遮擋：

```ts
const distance =
  Math.abs(player.row - cell.row) +
  Math.abs(player.column - cell.column)

const visible = distance <= visionRange
```

初始規則建議：

- 玩家移動視野：4 格。
- 據點視野：每個據點以自身位置為中心提供 6 格視野。
- 地圖瞭望塔視野：每座 `watchtower` 以自身位置為中心提供額外 3 格視野。
- 玩家目前可見範圍為玩家、據點與已啟用瞭望塔視野的聯集。
- 情報或遺物加成：後續擴充。

### 4.2 探索更新時機

以下時機更新探索資料：

- 建立初始遊戲狀態。
- 玩家移動成功後。
- 建造或啟用視野型建築後。
- 取得視野型事件或遺物後。
- Debug 地圖載入時依模式決定是否全圖揭露。

### 4.3 探索資料更新方式

```text
目前 visible 格子
→ 合併到 exploredCellIds
→ 已探索資料只增加，不因離開視野而消失
```

## 5. 地圖渲染規則

### 5.1 `unexplored`

- 顯示迷霧遮罩或未知色塊。
- 不顯示地形細節。
- 不顯示 Creature、巢穴、資源點、道具點與事件點。
- 不接受地圖物件互動。

### 5.2 `explored`

- 顯示已知地形。
- Creature 不顯示即時位置。
- 巢穴可依設計選擇顯示已知位置或暫時隱藏；MVP 建議先隱藏。
- 資源點與道具點可在發現後保留位置，但不顯示動態狀態。

### 5.3 `visible`

- 顯示允許公開的所有地圖物件。
- 可查看物件詳情。
- 可進行符合條件的攻擊、外功、採集與其他互動。

## 6. Store 與 UI 邊界

### 6.1 純函式

建議新增：

```ts
function getCellVisibility(
  state: GameState,
  playerId: string,
  cell: MapCell,
): VisibilityState
```

```ts
function canPlayerSeePosition(
  state: GameState,
  playerId: string,
  position: Position,
): boolean
```

```ts
function getPlayerVisionRange(state: GameState, playerId: string): number
```

### 6.2 `MapGrid`

- 只接收可見性結果或 visibility helper 所需資料。
- 不在 JSX 內重複計算視野規則。
- 依格子狀態決定迷霧、已探索與完整渲染。

### 6.3 Store 驗證

UI 隱藏不是完整規則，Store 仍需驗證：

- 普通攻擊目標必須在可見範圍內。
- 外功目標必須在可見範圍內。
- 巢穴、資源點、道具點與事件互動必須在可見範圍內。
- 視野外目標不得透過舊 preview 或快捷鍵操作。

## 7. 各物件可見性政策

| 物件 | 未探索 | 已探索但不可見 | 目前可見 |
|---|---|---|---|
| Creature | 隱藏 | 隱藏 | 顯示即時位置與狀態 |
| 巢穴 | 隱藏 | MVP 隱藏 | 顯示位置、血量與生成資訊 |
| 資源點 | 隱藏 | 可保留已知位置 | 顯示即時狀態與互動 |
| 道具點 | 隱藏 | 可保留已知位置 | 顯示並可互動 |
| 據點 | 隱藏或由任務揭露 | 保留已知位置 | 顯示完整資料 |
| 事件點 | 隱藏 | 依事件狀態決定 | 顯示並可互動 |
| 寶箱 | 隱藏 | 保留已知位置 | 顯示狀態與互動 |

## 8. 瞭望塔與視野建築

### 8.1 地圖防禦瞭望塔

- 建造後增加所屬據點周圍視野。
- 視野計算以瞭望塔自身位置為中心，並與玩家及據點視野合併。
- 不直接揭露全圖。
- 視野加成應能在地圖上被觀察到。

- 命名：`watchtower`「瞭望塔」。
- 不得將地圖防禦設施 `watchtower`「瞭望塔」與據點內建築混用。

### 8.2 後續視野能力

- 情報事件：暫時揭示區域。
- 遺物：增加玩家基礎視野。
- NPC 情報販子：揭示指定 Creature、資源點或巢穴位置。
- 中立瞭望塔：提供區域視野或永久探索資訊。

## 9. 例外處理

- 玩家沒有可見目標時，攻擊/外功模式不顯示可選高亮。
- 目標在預覽後離開視野，確認執行時必須失敗且不消耗行動。
- 未探索格不可因 marker 事件冒泡而觸發移動或互動。
- 若未來啟用 Debug `revealed` 模式，不應寫入正式探索資料，避免污染測試與正式狀態。
- 多人模式尚未支援前，不共享其他玩家的探索資料。

## 10. 開發階段

### Phase 1：基礎迷霧 MVP

- 新增 `VisibilityStateData`。
- 新增基礎視野距離與曼哈頓距離判定。
- 初始建立玩家周圍可見範圍。
- 初始建立玩家、據點與已啟用瞭望塔的可見範圍聯集。
- 玩家移動後更新 `exploredCellIds`。
- `MapGrid` 顯示未知遮罩。
- Debug 地圖使用 `fog` 模式，驗證正式迷霧規則。

### Phase 2：物件可見性

- 視野外隱藏 Creature。
- 視野外隱藏巢穴。
- 視野外隱藏資源點與道具點。
- 加入已探索位置保留規則。
- 攻擊、外功與物件互動加入 Store 視野驗證。

### Phase 3：建築與情報

- 瞭望塔增加視野。
- 情報事件暫時揭示區域。
- 遺物增加基礎視野。
- NPC 情報服務揭示指定目標。

### Phase 4：複雜視線規則

- 牆體遮擋。
- 森林或水域視野影響。
- 不同地形的探索距離差異。
- 多人玩家各自視野同步。

## 11. 驗收標準

### MVP 功能驗收

- 新遊戲不會顯示全圖所有互動物件。
- 玩家初始位置周圍符合基礎視野距離。
- 所有據點與已啟用瞭望塔的視野正確併入玩家可見範圍。
- 玩家移動後，新的格子變為 `visible` 並加入 `exploredCellIds`。
- 離開視野後，Creature 不再顯示。
- 視野外 Creature 與巢穴無法被攻擊。
- Debug 地圖仍可使用完整地圖視野測試所有既有功能。

### 測試方法

- 測試初始視野範圍。
- 測試移動後探索資料累積。
- 測試 Creature 進入與離開視野。
- 測試視野外攻擊/外功被 Store 拒絕。
- 測試 Debug 地圖依玩家、據點與瞭望塔視野顯示物件。
- 執行 `npm test`、`npm run lint`、`npm run build`。

## 12. 風險與控制

### 玩家迷路或不知道目標

- 保留已探索地形。
- 透過任務、據點或情報提供方向。
- 初期地圖安排至少一個明確可見目標。

### 測試效率下降

- Debug 地圖固定使用 `fog`，並保留快速重置探索資料的能力。
- 保留現有 Debug 測試按鈕。
- 允許測試快速重置探索資料。

### 資訊落差造成挫折

- 詳情 modal 顯示可見性與互動條件。
- 不因視野規則無預警摧毀玩家進度。
- 重要目標可透過任務或情報提前揭露。

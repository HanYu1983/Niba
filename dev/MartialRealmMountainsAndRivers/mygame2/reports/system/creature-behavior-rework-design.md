# 怪物行為與流派重構設計文件

## 1. 文件目的

- 重新設計怪物的「行為類型」與「流派」關係，取消攻城化與流派綁定行為的設定。
- 改為「流派 × 行為類型」隨機組合，避免後期怪物單一化（大家都用木屬性打攻城怪）。
- 讓所有行為類型的怪物都可能攻擊據點，但保留行為類型之間的戰略差異。
- 本文件為「設計基準與討論」；標記為「提案」的內容尚未實作，待討論確認後再拆分工程任務。

## 2. 現狀盤點

### 2.1 攻城化設定（兩處）⚠️ 需先在遊戲中移除

> **標注：以下兩個攻城化功能需先在遊戲中移除**（在重構行為/流派之前，先移除攻城化，讓怪物維持原本行為與流派）。

| 來源 | 觸發條件 | 效果 | 處理 |
|---|---|---|---|
| 巢穴生成時（`spawnCreaturesFromNests`） | `nest.behaviorType === 'sieger'` 或 `rollChance(攻城機率)` | 門派強制轉厚土流 | ⚠️ 移除 |
| 存活滿 20 回合（`convertLongLivedCreatures`） | `round - spawnedRound >= 20` | 行為轉攻城型、門派轉厚土流 | ⚠️ 移除 |

- 攻城機率：基礎 30%，每 10 回合 +10%，上限 60%。
- 問題：後期怪物大量轉為厚土流（土屬性），玩家傾向用木屬性應對，導致屬性單一化。
- **移除範圍**：`spawnCreaturesFromNests` 中的 `becomesSieger` 判斷、`convertLongLivedCreatures` 函式及其呼叫點、相關常數（`CREATURE_SIEGE_CONVERSION_CHANCE` 等）。

### 2.2 流派綁定行為 ⚠️ 需移除

> **標注：行為綁定流派的設定需移除**（行為類型與流派改為隨機組合，不再綁定）。

- `CREATURE_SCHOOL_BY_BEHAVIOR`：行為 → 固定門派。
  - scavenger → 寒水流、hunter → 疾風流、sieger → 厚土流、guardian → 金身流、wanderer（拾荒型）→ 赤焰流、roamer（游蕩型）→ 虛靈流。
- **開局游蕩妖物**：固定 `roamer` → `void-spirit`（綁定）。
- **巢穴怪物**：`schoolId` 與 `behaviorType` 已各自隨機，非綁定。
- **移除範圍**：`CREATURE_SCHOOL_BY_BEHAVIOR` 作為強制 fallback 的依賴（`getCreatureSchoolId` 中 `creature.schoolId` 為空時的回退）、開局游蕩妖物固定 `roamer` + `void-spirit` 的設定。
- **保留**：`getCreatureSchoolId` 的 `creature.schoolId` 優先邏輯（怪物有明確流派時沿用），僅移除「行為 → 流派」的強制對應。

### 2.3 各行為目標優先序（`getCreatureTargetGroups`）

| 行為 | 目前目標優先序 | 會攻擊據點？ |
|---|---|---|
| sieger | 據點 → 防禦 → 資源 → 玩家 | ✅ |
| scavenger | 資源 → 玩家 | ❌ |
| hunter / guardian / wanderer | 玩家 → 資源 | ❌ |
| roamer | 玩家 | ❌ |

- `selectCreatureTarget` 另有兩條前置規則（**將與目標優先權統一設計，見 4.1**）：
  1. 三格內箭塔 → 優先攻擊箭塔。
  2. 警戒範圍內有玩家 → 優先追蹤玩家（蓋過據點/資源）。

### 2.4 怪物警戒距離（`CREATURE_AGGRO_RANGES`）

| 行為 | 中文名 | 警戒距離 |
|---|---|---|
| scavenger | 掠奪型 | 5 |
| hunter | 獵殺型 | 6 |
| sieger | 攻城型 | 7 |
| guardian | 守巢型 | 5 |
| wanderer | 拾荒型 | 4 |
| roamer | 游蕩型 | 2 |

- 警戒距離 = 怪物「發現目標」的距離；目標在警戒距離內，怪物才會去追。
- 各類型警戒距離不同，行為差異由「主要目標」與「優先序」承擔，警戒距離**維持原本設定**。

## 3. 設計目標

1. **取消攻城化**：移除兩處攻城化邏輯，巢穴怪物維持原本行為與流派。
2. **取消流派綁定行為**：開局游蕩妖物改為隨機行為 + 隨機流派；巢穴怪物維持已隨機。
3. **所有行為類型都可能攻擊據點**：但保留行為類型之間的戰略差異。
4. **避免屬性單一化**：隨機組合後，怪物屬性多樣，玩家需依實際怪物屬性應對。

## 4. 設計方案（提案）

### 4.1 目標選擇優先權（統一設計）

> **箭塔（最優先）→ 主要目標（依類型不同）→ 玩家 → 據點**

將現有兩條前置規則（箭塔、玩家）與各類型主要目標、據點整合為**單一目標選擇流程**，所有規則在同一優先權內依序判斷，不再有「前置規則」與「目標優先序」分離。

#### 統一流程（`selectCreatureTarget`）

```
1. 若行為是 roamer → 維持現狀（只追警戒範圍內玩家，不參與據點/箭塔/資源）
2. 找箭塔警戒範圍（5 格）內最近的箭塔 → 攻擊
3. 找「主要目標」（依類型，見下表）→ 在警戒範圍內則攻擊
4. 找警戒範圍內最近的玩家 → 攻擊
5. 找警戒範圍內最近的據點 → 攻擊
6. 否則 null（巡邏）
```

- 主要目標、玩家、據點以**怪物警戒範圍**為搜尋範圍。
- **箭塔以「箭塔警戒範圍（5 格）」為搜尋範圍**，與怪物警戒範圍不同。
- 步驟 2–5 依序判斷，命中即返回，不再有「前置規則蓋過目標優先序」的分離邏輯。
- **箭塔最優先**：所有類型（含 sieger）在箭塔 5 格內會先拆箭塔，離開箭塔範圍後才繼續追主要目標。這實現「箭塔吸怪」的設計意圖。

#### 每個類型的「主要目標」（提案，待確認）

| 行為 | 主要目標 | 找不到主要目標時 |
|---|---|---|
| sieger | 據點 | 箭塔 → 玩家 → 據點 |
| scavenger | 資源 | 箭塔 → 玩家 → 據點 |
| hunter | 玩家 | 箭塔 → 據點 |
| guardian | 巢穴附近的玩家 | 箭塔 → 據點 |
| wanderer | 道具點 | 箭塔 → 玩家 → 據點 |
| roamer | 玩家（維持現狀） | 維持現狀 |

> **sieger 行為**：sieger 的主要目標是據點，但在箭塔 5 格內會先拆箭塔（箭塔最優先），離開箭塔範圍後才衝據點。sieger 仍是「據點殺手」，但箭塔能攔截其進入 5 格。

#### guardian 與 wanderer 設計（已確認）

hunter、guardian、wanderer 原本設計相同（主要目標皆為玩家），hunter 合理，guardian 與 wanderer 已各自定位：

**guardian（守巢型）**
- 定位：守護巢穴，不主動遠離巢穴追擊，而是守衛巢穴周邊。
- 主要目標：**巢穴附近的玩家**（進入巢穴警戒範圍的玩家）。
- 找不到主要目標時：箭塔 → 據點（守衛巢穴周邊的防禦/據點）。
- 差異點：不會像 hunter 主動追擊遠方玩家，而是守在家裡。
- 實作考量：guardian 有 `homeNestId` / `homePosition`，可以「巢穴為中心」判斷玩家是否進入守衛範圍。

**wanderer（拾荒型）**
- 定位：遊蕩探索，尋找道具點，不主動獵殺玩家。
- 主要目標：**道具點**（拾荒尋寶，找到道具點就摧毀/吃掉）。
- 找不到主要目標時：箭塔 → 玩家 → 據點。
- 差異點：主要目標是道具點而非玩家，較被動。
- 實作考量：wanderer 主要目標道具點，找不到道具點時才依共同順序（箭塔 → 玩家 → 據點）。

### 4.2 道具點機制變更（統一不再生成）

> **標注：道具點被吃掉（玩家拾取或怪物摧毀）後，統一不再生成。**

- 目前機制：道具點被移除後，`replenishInteractionPoint` 會重生一個新道具點。
- 變更後：道具點被吃掉後**不再生成**，地圖上的道具點為**有限資源**。
- **維持**：探索事件點（`explorationEvents`）被解決後仍會生成（維持現狀）。
- 影響：道具點會越用越少，玩家需透過商店、事件、掉落等其他來源取得道具/裝備。
- 實作範圍：`replenishInteractionPoint` 中 `removedItemPoint` 分支改為不重生；`moveCreatures` 中怪物摧毀道具點後也不重生。

### 4.3 開局游蕩妖物

- **維持原本**：固定 `roamer` + `void-spirit`，只追警戒範圍內玩家，不參與據點攻擊。
- 理由：避免開局就出現攻城型游蕩妖物直接衝據點，對前期玩家壓力過大。

### 4.4 箭塔範圍（已確認）

> **箭塔警戒範圍 = 5 格。** 怪物在箭塔 5 格內，優先轉向拆箭塔。

- **已確認**：箭塔警戒範圍統一為 **5**（怪物在箭塔 5 格內優先拆箭塔）。
- 怪物自身警戒範圍**維持原本設定**（見 2.4）。
- **設計意圖**：箭塔有「吸怪」功能（攔截進入 5 格的怪物），但非萬能（sieger 警戒 7，在 6-7 格時仍可能無視箭塔衝據點），促使玩家思考建築策略。
- 涵蓋效果：scavenger（5）、guardian（5）、wanderer（4）完全被攔截；hunter（6）、sieger（7）在 5 格內被攔截。
- 箭塔射程維持原本（箭塔 2、進階箭塔 3、小型箭塔 1），不調整。

### 5.5 怪物警戒範圍（已確認，維持原本）

- 目前警戒範圍：scavenger 5、hunter 6、sieger 7、guardian 5、wanderer 4、roamer 2。

### 5.6 目標狀態機（已評估，不採用）

- 曾考慮設計「目標狀態機」（據點追蹤 / 玩家追蹤 / 防禦追蹤等狀態，怪物依類型與當下情況切換狀態）。
- **結論：不採用，維持目前的「每回合重新選目標」設計。**
- 理由：
  - 需求是「目標優先權」的調整，目前的 `selectCreatureTarget` 依優先權選目標已足夠。
  - 狀態機的價值在於「鎖定目標的執著感」，非目前核心需求。
  - 狀態機需在 `CreatureState` 新增 `currentState` / `lockedTargetId`，影響存檔結構，成本較高。
- 若未來需要「怪物追蹤途中不換目標」的執著感，可加輕量「目標鎖定」（`lockedTargetId`），無需完整狀態機。

## 6. 影響與平衡考量

- **據點壓力**：所有類型都可能打據點後，玩家據點被攻擊頻率上升。需評估是否調整據點血量/防禦。
- **行為差異**：若所有類型都打據點，行為類型之間的區別可能變小，需靠主要目標與優先序維持差異。
- **開局難度**：開局游蕩妖物維持現狀，避免前期壓力過大。
- **內功一致性**：隨機流派後，內功由 `schoolId` 推導，天然一致，不會再出現門派與內功元素矛盾。

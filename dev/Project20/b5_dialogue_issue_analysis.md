## 二、可能原因（由 v2 觀察推導）

### 2.1 H3 內建 TTS 對長句與密度過高的政治術語斷句失敗 [最直接原因]

觀察這句結構：

```
「真實？在聯邦面臨外部經濟封鎖的非常時期，任何偏離官方定調的『數字』，...」
          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
          14 字、全部是抽象政治術語、無自然停頓點
```

- 「在聯邦面臨外部經濟封鎖的非常時期」是一個**單一介詞片語**（14 字），TTS 在這個區間內找不到自然的語氣斷點，容易壓縮後失真。
- 「聯邦」「封鎖」「非常時期」三詞都是高資訊密度的抽象詞，拼在一起時音節節奏異常緊湊，模型的聲學模型容易失控。
- 相比之下，「任何偏離官方定調的數字」與「這不是科學，這是背叛」有「數字/這是/不是」這類語氣停頓，TTS 處理較好。

**對策建議：** 在「聯邦面臨封鎖」與「非常時期」之間插入自然斷點（逗號），或把 14 字片語拆成兩個短語，讓 TTS 有呼吸點。

## 三、可能原因（由 v3 觀察推導）

### 3.1 敏感內容處理 → 替換 [審查疑慮，中高可能]

**支持「審查」假設的證據：**
1. 三次失敗都集中在同一類政治敏感語意：「外部經濟封鎖／懷疑官方數字／背叛」——正是中資模型的審查高風險區（本片劇情為「政府壓制真實、起訴說真話的孩子」）。
2. v3 的失敗方式不是「失真」而是**整句換料**——把沒有 `<d>` 包的 summary 文字唸成台詞。這像安全管線把「拒唸目標」改從 prompt 抓其他文字填充，而不是普通語音合成錯誤。

**反駁「純審查」的證據：**
1. v2 失敗是**部分失真**、其餘句子完好——若是整句封鎖，應是整段換料而非只壞一句。
2. v3 被抓去唸的 summary 文字裡有 `「懷疑官方數字」`「「背叛」」——ref2va 有已知行為：**會把所有帶引號（「」『』"」）的文字視為「可唸的台詞候選」**。把 meta 描述加了引號，等於主動提供替換選項，模型就抓了。

**初步結論：**「敏感主題觸發替換」＋「引號誘餌」兩件事疊加。審查介面很可能存在，但**會被可避免的 prompt 設計放大**。

## 六、最終結論（v5 驗證）

### 核心原因：`summary`（與 `<d>` 以外的敘述欄）污染了台詞生成

模型把 `<d>` 以外的文字當成「可朗讀內容」，尤其當出現**中文完整句**時（如 summary 的
「檢察官冷笑一聲轉向陪審團，將懷疑官方數字上升為背叛……」），它會優先唸那些句子、覆蓋掉
`<d>` 內的對白。這解釋了為何每次失敗都是「唸出 summary 文字」——與敏感內容、聲學、審查無關。

### 成功版本的四大原則（寫入 guide，對白區塊一律套用）

1. **summary 不出現任何可能被朗讀的句子**：只寫名詞片語/關鍵字，如 `Reference-based courtroom scene. One visible speaker only.`
2. **summary 不出現台詞關鍵字**：避免把「懷疑官方數字」「背叛」等對白用詞寫進 summary。
3. **shot 以外的區域不出現中文完整句**：subject_definitions / summary / retention_analysis /
   soundscape 等欄位都禁止完整中文句，中文只存在於 `<d>` 內。
4. **所有需要說的內容只放進 `<d>`**：對白是唯一被朗讀的來源，欄位分工徹底隔離。

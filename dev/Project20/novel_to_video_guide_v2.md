# 小說 → 視頻提示詞轉換指導（v2，通用版）

> **範圍**：將長篇小說轉換為「一支獨立 r2v 影片＝一個區塊」的全流程方法論。
> **通用性**：本文不綁定任何特定小說。以 story1（《共識協議》Ch2）為案例的完整實作，
> 請見 `example3.md`（區塊總表、參考圖表、全部 30 支提示詞）；本文僅在必要處對其做引用。

---

## 一、核心概念：一支影片 = 一個區塊

> **一個區塊 = 一支獨立的 `gen_r2v_video`（可獨立生成、可獨立重跑、可獨立檢查）。**

不要用「章節」或「景」當單位，也不要一支影片塞多個節拍。理由是：

- 一支影片塞太長，某一鏡頭的失誤無法單獨修正，必須整支重跑。
- 每支固定 seed：出錯（如歪腔調、角色漂移）只重跑該支，不影響其他。
- 每一支都有界定的時間範圍與音訊內容，方便相加成完整成品。

### 範例實作

Ch2 用 30 支區塊（B0–B29）覆蓋約 230 秒，參考圖只建置 9 張就支撐全部區塊：
見 `example3.md`「總表：區塊分割與計秒」。

## 二、三種區塊型別

所有區塊分三類，對應三種音訊與提示詞寫法（引用 `example3.md` 的實作分類）：

| 型別 | 音訊 | 提示詞處理 | 計秒 |
|------|------|-----------|------|
| **場景** | 無對白、無旁白 | `speaker_constraints` 寫 `No one speaks / No narration / No voice-over`；`detailed_description` **完全不寫 `<d>`**；`overall_soundscape` 只寫環境音 | 看動作節拍，通常 1–8s |
| **對白** | 只有畫面內角色開口 | `<d>` 內逐字寫對白；`speaker_constraints` 指名 `Only <Subject N> speaks` | **4 字/秒**（台灣腔普通話慢讀） |
| **旁白** | 只有旁白，畫面角色不開口 | `<d>` 承載旁白（角色「不發聲」由 `speaker_constraints` 排除）；多支旁白**共用同一支 seed** | **5 字/秒**（更平更快） |

### 計秒規則

- 對白：逐字數中文字數 ÷ 4，留緩神餘裕再進位。
- 旁白：逐字數中文字數 ÷ 5，留緩神餘裕再進位。
- 場景：由動作所需的鏡頭數粗略估時，寧短勿長。

### 三種型別與 seed 策略

- 一般區塊（場景/對白）：**每支獨立 seed**，不共用。
- 旁白區塊：**全片共用一支旁白 seed**（實作採用 `310000`），讓聲線跨支穩定。

## 三、參考圖建置（Step 1：一次性，全片共用）

> 參考圖是本方法的核心。所有區塊一律透過 `ref_image_0 / 1 / 2` 重複取用同一批圖，
> **不逐塊重出圖**。建置一次即成本固定，之後每支 r2v 只需傳檔名。

### 建置流程

```
Step 1a | 角色肖像（每個要上鏡的角色一張）
Step 1b | 場景定場圖（每個主要場景一張，可跨章共用）
Step 1c | 特殊道具/設備圖（電視牆、直播攝影機等，有需要才出）
```

每張圖用 `gen_zit_image`（Z-Image Turbo）生成，規格：

- **尺寸 832×1248（2:3 直式）**：r2v 的 `ref_image_size: "match"` 會把參考圖縮放到影片框架，出圖就接近 2:3 才不會裁掉構圖重點。
- prompt 內寫死角色的外觀錨點（髮型、年齡、衣著、膚色），確保跨圖一致。
- 存放到 `output/<scene_或_char>_ref/` 專用目錄，檔名用有意義的前綴（如 `zimage_00016_.png` + 目錄名辨識用途）。

> **範例（引用）**：`example3.md`「參考圖管理表」——9 張圖（林墨/檢察官/艾倫/法官 + 法庭全景/辯護席/攝影機/走廊/電視牆）支撐全部 30 支區塊。

### 反例警示

- 參考圖雜圖殘留是**污染源**：workflow JSON 中未使用的 `LoadImage` 節點若殘留舊檔名，會被偷偷當額外參考圖餵進模型。
  修法：未提供 `ref_image_N` 時，MCP 層直接刪除該節點與其連線（見 `mcp_core.mjs buildR2vWorkflow`），檔案內預設值一律清空為 `""`。

## 四、區塊分割流程

```
第 1 層  全書 → 章節圖        （列出各章功能與情緒走向）
第 2 層  章節 → 三型別區塊    （逐一標示 場景 / 對白 / 旁白 + 計秒）
第 3 層  區塊 → 參考圖分配    （對照參考圖管理表填 ref_image_0/1/2）
第 4 層  區塊 → 六欄位提示詞  （見第 5 節格式）
```

### 4.1 切割判斷

- **進區塊的**：氛圍鏡頭、象徵鏡頭、強動作、金句台詞、節拍三連（質問→數據登場→對方語塞）。
- **跳過/濃縮的**：純政策論述、運算細節、哲學長對話（只留 1–2 句金句）、純過場、冗長內心獨白。
- 對白每支最多 1–2 句的承載力（字數對應秒數，見計秒規則）；句子別太長。

### 4.2 產量管理

單支影片建議最短 1s、單一章節總區塊數落在可管理的量（整本書 ≤ 50 支為佳）。
一支 ≥ 20s 的對白區塊風險高（語音易漂移），能拆就拆。

## 五、r2v 六欄位提示詞（官方 Ref2VA 格式）

> MiniMaxH3ReferenceToVideo 是「全參考模式」，官方 schema 為**六欄位**。
> 早期 A/B/C/D 自創結構沒有音訊欄位，會讓模型自動腦補旁白——已全面棄用。

```text
subject_definitions:
<Subject 1> is {角色/場景} from <Picture 1>: {外觀關鍵特徵（全英文）}

summary:
{僅英文名詞片語/關鍵字，單句描述影片與參考關係}

retention_analysis:
<Subject 1>: fully_preserved.     <Subject 2>: fully_preserved.

speaker_constraints:
Only <Subject 1> speaks.          // 對白區塊：指名誰說話
No narration. No voice-over.      // 對白/場景區塊：排除旁白
No off-screen voice.

detailed_description:
{風格 1-2 句}
[Shot 1]
00:00-00:0X
Action: {逐鏡：構圖/主體/動作/鏡頭運動/表情}
Dialogue:
<Subject 1> says:
<d>
[中文]
{逐字對白，每句獨立換行}
</d>

overall_soundscape:
{環境音 + 腔調錨點句（見 5.2）}

non_diegetic_music:
{配樂 1-3 句}
```

### 5.1 四原則（對白/旁白區塊一律套用）

1. `summary` 只寫英文名詞片語，**不寫任何中文完整句**。
2. `summary` 不出現台詞關鍵字，避免被當成可朗讀內容。
3. 除 `<d>` 外，任何欄位（subject_definitions / summary / retention_analysis / soundscape）**不出現中文完整句**；中文只在 `<d>` 內。
4. 所有要發聲的內容只放進 `<d>`；對白是唯一被朗讀的來源。
   `<d>` 內每句獨立換行，製造氣口，TTS 逐句處理更穩。

### 5.2 腔調錨點（實測 2026-09 驗證有效）

`ref2va` 的中文聲線**常與 seed 耦合出方言腔**（例如某 seed 固定導出粵語腔）。處理：

- 不要只改 `<d>` 的語言標籤（`[中文]`→`[普通話]` 實測無效）。
- 在 `overall_soundscape` **逐字寫念腔**當錨點。
- 標準錨點句（已驗證有效）：`All spoken lines are delivered in Taiwan-accented Standard Mandarin (台灣腔普通話), no Cantonese.`
- 加強版：另在 `speaker_constraints` 加負向排除（`never Cantonese / never Hong Kong accent`）、在 `Action :` 段補充正向念腔描述、在 `<d>` 前一行聲明腔調。
- **歪腔 seed 黑名單**：每支區塊若實測歪腔，將該 seed 記入黑名單並換 seed 重跑（見下一節）。

### 5.3 seed 策略

- 每支獨立 seed；**旁白區塊共用旁白 seed**。
- 提交前查黑名單；實測歪腔的 seed 記入黑名單（紀錄於專案文件「腔調錨點」段落），換用未使用的新 seed。
- 需要穩定重跑：固定 seed = 固定腔調，所以修正提示詞後要**同時換 seed**，不能只改字。

### 5.4 特殊符號唸法陷阱

`<d>` 內凡會被唸出的文字，一律避免符號與阿拉伯數字：

- `2%` → `百分之二`、`15%` → `百分之十五`（禁止 `百分之2` 混寫；實測 `%` 會被唸成「PiFen」怪音）。
- **畫面可見文字**（圖表數字、電視牆標題）不被唸出，可保留原始符號；但在鏡頭描述中標明 `visible on-screen text`，與 `<d>` 的分開。

### 5.5 音訊欄位不可省略

`overall_soundscape` / `non_diegetic_music` 必須明寫。不改動它們，模型會自己發明旁白或疊加無關聲音。

## 六、生產流水線（每支影片的操作步驟）

### 6.1 生成

1. **取區塊**（自總表）。
2. **分配參考圖**：按參考圖管理表填 `ref_image_0 / 1 / 2`（0 通常是主角肖像，其次場景圖；`ref_image_N` 可省略，省略即不餵，ML 層會刪節點）。
3. **選工具**：一律 `gen_r2v_video`；精準首尾幀銜接才用 `gen_i2v_video`（首尾幀皆自帶）；純文字急件可用 `gen_t2v_video`（一致性最弱）。
4. **提交**：帶 `duration`、`seed`、`ref_image_*`、`out`（輸出子目錄名）。

### 6.2 解析度統一（合併必需）

- **固定解析度**（r2v workflow 預設）：`352 × 608`，比例 `2:3`。
- 全片一律同一組，不要為個別區塊切 16:9 / 1:1。
- 參考圖不影響輸出尺寸（`ref_image_size: match` 縮放至框架）。
- 各家 MCP 反應的路徑輸出是一致的；合併時再做統一再編碼。

### 6.3 下載與追蹤

- 提交後回傳 `prompt_id`，背景自動下載至 `output/<out>/`。
- 背景下載若因 server 重啟/佇列取消而失效（本地無檔、回報 timeout）：
  1. `query_history` 查該 `prompt_id` 是否存在於 ComfyUI 歷史、輸出檔名為何。
  2. `download_from_history` 直接以 `prompt_id` 從歷史重新下載（自動寫回 `.txt` meta）。
- 批次追蹤：可用每 30 秒輪詢 history 的腳本背景跑（見 `ai_gen_video/history_poller.mjs`），
  新完成即下載，直至全部完成。

### 6.4 合併

依區塊順序把完成的 `.mp4` 依序傳 `merge_videos(files=[...], resolution="352:608", out=...)`：

- `resolution` 維持全片相同值；輸入同解析度時 scale+pad 為 no-op、直接併流。
- 合併前確認每支影片解析度/幀率一致。

## 七、產出前自檢清單

- [ ] 每個區塊是否只含「一個主要事件」？塞太多就再拆。
- [ ] 每支是否有獨立觀看價值（不是前後支拼接才懂）？
- [ ] 對白/旁白是否逐字對照原文、未發明、未省略？
- [ ] `<d>` 內會被唸的文字是否已將 `%`、`&`、阿拉伯數字改為中文寫法？
- [ ] 型別與提示詞對應：場景 → 完全不寫 `<d>`；對白 → 指名 `Only <Subject N> speaks`；旁白 → 角色不發聲且共用旁白 seed。
- [ ] `speaker_constraints` 是否排除了旁白/第三人聲（避免腦補旁白）？
- [ ] `overall_soundscape` / `non_diegetic_music` 是否明寫？
- [ ] 腔調錨點句 / 負向排除是否在每支對白與旁白區塊中？
- [ ] seed 是否查過黑名單？旁白是否用旁白 seed？
- [ ] 參考圖：用到的 `ref_image_N` 是否確實存在？未用的是否沒帶入（避免殘留污染）？
- [ ] 解析度是否全片統一（352×608）、合併順序是否正確？
- [ ] 有沒有長辯論硬塞進一支？應拆分。

## 八、於此文件實作過的重要教訓（2026-09）

- **參考圖殘留污染**：workflow 未用到的 LoadImage 節點殘留舊檔名 → 被當參考圖餵入。已由 MCP 層在 `buildR2vWorkflow` 以「未提供即刪除節點+連線」根治，JSON 預設值清空。
- **歪腔與 seed 耦合**：修正腔調不能只改 `<d>` 標籤；要 soundscape 錨點 + 黑名單換 seed。
- **背景下載脆弱**：server 重啟/佇列取消會讓自動下載失效，需 `query_history` + `download_from_history` 復原。
- **MCP 背景任務錯誤隔離**：非同步下載區段每檔案 try/catch，單一檔案失敗只印 log 不中斷整支 job，外層 `.catch` 防止錯誤向上傳播（`mcp_core.mjs startBackgroundJob`）。

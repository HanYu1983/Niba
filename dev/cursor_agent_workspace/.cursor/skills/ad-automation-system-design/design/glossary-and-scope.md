## 名詞

| 名詞 | 定義 |
|------|------|
| 廣告列（Ad row） | JSON 陣列 `items` 中的一筆物件，代表一則待評估的廣告。 |
| 輸入封套（Input envelope） | 單一 JSON 檔案的外層物件，含 `startDate`、`endDate`、`items` 等（見 [輸入資料模型](input-model.md)）。 |
| 自動化啟動期間 | 由 `startDate`、`endDate` 界定的區間；條件或下游可用以判斷「是否在有效期內」。（精確語意見該文「日期語意」小節） |
| 進入點（Entry point） | 可執行程式（如 `App1`、`App2`）；代表**本次要處理的一類廣告列表**：輸入資料夾、**執行期間綁定的一組條件**、結果輸出路徑等，皆於啟動時決定。 |
| 編碼廣告 ID（Encoded ad id） | 以 `.` 串接各層代碼的字串；層級與段數由**該平台**的編解碼實作定義。 |
| 廣告名稱（`adName`） | 對應階層名稱（`accName.capName.grpName.adName`），用於結果 JSON 稽核／除錯展示；與 `adId` 一起作為人可讀識別。 |
| 階層路徑（Decoded path） | 解碼後的結構化識別，供**下游開關系統**對正確層級下指令。 |
| 平台（Platform） | 廣告生態識別子（字串），例如 `meta`、`google`。 |
| 地區路由鍵（`area`） | 地區代碼或路由鍵，供共用路由專案將其映射為特定平台 API 所需的地區／region 代碼。 |
| 條件集合（Condition set） | 對單列做評估的抽象；**由該進入點專案**提供實作，可含 API 呼叫。 |
| 決策列（Decision row） | 單列評估結果，寫入**結果 JSON** 的 `items` 中。 |
| 下游開關系統 | 讀取結果 JSON、依平台呼叫 API 或既有流程**實際啟停廣告**的系統；**不在本文件「條件判斷端」必實作範圍內**，但結果格式需滿足其契約。 |
| 自定義 ID（建議 JSON 鍵：`credentialCustomId`） | **非秘密**的邏輯鍵；與 `platform`（及可選命名空間）一併送入**憑證管理共用專案**，解析出該廣告列在**查詢 API**與**操作 API**應使用的憑證組。同一列在條件端查詢與下游操作必須能對到**同一組**憑證解析結果。 |
| 憑證管理共用專案 | 集中提供「`(platform, credentialCustomId[, 環境])` → 憑證物料」的解析介面；實際來源可為本機加密檔、雲端祕密管理、環境變數對照表等，**對業務程式只暴露已解析的設定物件或 factory**。 |
| 平台共用專案（每平台一個） | 該廣告平台的 **查詢**與**操作（開／關等）** API 用戶端或封裝層；內部透過憑證管理專案取得與 `credentialCustomId` 對應的憑證後再發請求。 |
| 地區路由共用專案（AdAreaRouting） | 集中管理「輸入 `area` → 對應平台 API 所需的地區／region 代碼」對照；供條件端在呼叫平台查詢／操作 API 前解析。 |
| 操作批次（API batch） | 下游在**同一** `(platform, credentialCustomId)` 組內，依該平台 API 允許的批量上限切分的子集合；**預設每批最多 100 筆**（可設定或由平台封裝覆寫）。 |
| 錯誤匯流排（Error sink） | 主程式／進入點使用的抽象介面（如 `IErrorSink`），將錯誤以統一方式送出；實作可為 Console、**Slack**、複合等，與結果 JSON `errors` 可並存。 |

## 範圍與非範圍

### 本系統（條件判斷端）範圍

- 依進入點參數讀取**指定資料夾內所有輸入 JSON**（見 [輸入資料模型 — 多檔合併](input-model.md#folder-merge)），解析、驗證、合併為邏輯上的單一批次。
- 載入 `startDate` / `endDate`，並注入評估上下文供條件使用。
- 逐列執行該進入點綁定的條件，產出決策。
- 寫出**結果 JSON**（見 [結果 JSON](result-json.md)），供下游消費。

### 非範圍（或由下游／別專案負責）

- 實際呼叫各廣告平台 API 完成開／關（由**下游開關系統**依結果 JSON 執行）。
- 規則的視覺化編輯器。
- 與企業排程的深度整合（可先由外部在「有效期內」觸發進入點）。
- 即時串流增量更新（第一版以批次、多檔合併為主）。

### 預留（設計已涵蓋，實作可後補）

- 階層編解碼、平台查詢抽象：結果 JSON **不要求**攜帶解碼路徑（`decodedPath`）；需要時由下游廣告操作專案依 `adId` 與該平台編解碼器解碼取得目標層級。
- **憑證管理共用專案**與**各平台共用專案**：條件內查詢、下游操作、兩端需共用同一解析規則與金鑰來源設定。

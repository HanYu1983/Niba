# 概覽與目標

[← 回到索引](../../../../project1/docs/SYSTEM_DESIGN.md) · [下一篇：名詞與範圍 →](glossary-and-scope.md)

在多平台投放廣告時，常需依營運條件（時段、預算、庫存、活動檔期、風控等）決定**是否讓某則廣告處於可投放／啟用狀態**。本系統（條件判斷端）負責：

1. **接收**結構化的廣告清單（JSON）：**封套外層**載明**所屬平台**與 **`credentialCustomId`**、**自動化啟動期間**（`startDate`、`endDate`）；`items` 內每列至少含**廣告識別**（`adId` 等），與外層平台／憑證鍵對應。
2. **支援多份輸入**：由**進入點**啟動時指定**輸入資料夾**，讀取資料夾內**所有**符合副檔名的 JSON，合併為本次執行的待評估集合。
3. **逐列評估**該進入點綁定的**一組條件**（可含 async／外部 API），產出每列的**開或關**決策與附帶脈絡。
4. **寫入結果 JSON**；**實際對廣告平台下指令（開／關）由另一套系統**讀取結果 JSON 後執行，本系統與其以**檔案契約**銜接。

## 設計重點（精簡）

- **條件邏輯與實際開關執行解耦**。
- **廣告識別**以平台專屬的「階層編碼字串」貫穿輸入／輸出。
- **`credentialCustomId`**（與 **`platform`**）在**輸入封套外層**（每檔一份）；評估與結果 JSON 仍**逐列**帶出相同鍵，經**共用憑證管理**解析查詢／操作所需 API 憑證；**憑證永不進 JSON**。
- **條件實作**由各可執行進入點專案指定；輸入可**多檔**。
- **憑證管理**與**各平台 API（查詢＋操作）**以**共用專案**承載，條件端與下游一致引用。

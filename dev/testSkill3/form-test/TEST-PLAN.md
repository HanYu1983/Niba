# 表單測試計畫：測試資料、流程、響應式、錯誤訊息與控制台監控

## 測試資料（可直接貼入表單）

| 欄位 | 正確範例 | 錯誤範例（用於觸發驗證） |
|------|----------|---------------------------|
| 姓名 | `王小明` | 空白 或 `王`（少於 2 字元） |
| Email | `test@example.com` | 空白 或 `not-email` |
| 電話 | `0912345678` 或 `02-1234-5678` | `abc` 或 `123`（少於 8 位） |
| 方案 | 任選一項 | 不選（留「請選擇」） |
| 備註 | 選填，最多 200 字 | — |

---

## 操作流程（按步驟點擊）

1. **步驟 1**
   - 先**不填任何資料**，直接點「下一步」→ 應出現錯誤訊息（姓名、Email）。
   - 再依序填入**錯誤範例**（姓名只打 `王`、Email 打 `x`）→ 點「下一步」→ 應出現對應錯誤。
   - 改為**正確範例**：姓名 `王小明`、Email `test@example.com`、電話 `0912345678` → 點「下一步」→ 應進入步驟 2。
2. **步驟 2**
   - 不選方案點「下一步」→ 應出現「請選擇方案」。
   - 選擇「專業方案」、備註可填「測試備註」→ 點「下一步」→ 進入步驟 3。
3. **步驟 3（確認）**
   - 檢查摘要是否與輸入一致。
   - 點「送出」→ 應出現 alert「表單已送出（測試用）」；控制台應有一筆 `表單送出` 的 log。

可隨時點上方「步驟 1 / 2 / 3」在已解鎖的步驟間切換。

## 響應式設計驗證

- **桌面**：容器最大寬度約 480px，置中。
- **窄螢幕（如 &lt; 400px）**：內距縮小、輸入字體 16px（避免 iOS 縮放）。
- 請在 Chrome DevTools 切換裝置模式（手機/平板/桌面），確認：
  - 按鈕與輸入框寬度 100%、可點擊區域足夠。
  - 步驟指示器在窄螢幕會換行（flex-wrap）。
  - 無橫向捲軸、文字不被裁切。

## 錯誤訊息驗證清單

| 情境 | 預期錯誤訊息 |
|------|----------------|
| 姓名空白 | 「請輸入至少 2 個字元」 |
| 姓名僅 1 字元 | 「請輸入至少 2 個字元」 |
| Email 空白 | 「請輸入 Email」 |
| Email 格式錯誤 | 「請輸入有效的 Email 格式」 |
| 電話格式錯誤（如 abc） | 「電話格式不正確（8–20 位數字）」 |
| 方案未選 | 「請選擇方案」 |

錯誤出現時，對應欄位應有紅框、下方顯示上述文字。

## 監控控制台 JavaScript 錯誤

1. 開啟 DevTools：`F12` 或 右鍵 → 檢查 → **Console** 分頁。
2. 勾選「Preserve log」（保留 log），避免換頁時清空。
3. 測試過程中預期：
   - **不應出現** 紅色錯誤（如 Uncaught TypeError、undefined 等）。
   - 送出表單後應出現一筆灰色/一般 log：`表單送出` 與表單資料物件。
4. 若出現任何紅色錯誤，請記錄錯誤訊息與發生步驟（例如：點「下一步」時、切換步驟時、送出時），以便除錯。

## 如何開啟測試頁

- 直接用瀏覽器開啟本目錄的 `index.html`：
  - 雙擊 `form-test/index.html`，或
  - 在專案根目錄用本機伺服器（若有的話）開啟對應路徑。
- 建議使用 Chrome 或 Edge，方便使用 DevTools 裝置模式與 Console。
